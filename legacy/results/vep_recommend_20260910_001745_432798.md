# VEP Recommendation

**Date:** 2026-09-10T00:17:45.433134

## User Query
I am working with whole exome sequencing data from a cohort of zebrafish tumor models where I have identified several somatic SNVs and small indels by comparing the tumor DNA to matched germline samples. My primary goal is to identify which of these mutations in the protein-coding regions are likely to be pathogenic, so I need a way to assess their potential impact on the amino acid sequence and overall protein function to help prioritize candidate driver mutations for further study.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (zebrafish)
- **origin**: somatic (comparing tumor DNA to matched germline)
- **variant_size_class**: small (SNVs and small indels)
- **region_focus**: coding (protein-coding regions)
- **analysis_goal**: clinical-interpretation (identifying pathogenic mutations and driver candidates)

### 2. Recommended Options
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for identifying the transcript type (e.g., protein_coding) to confirm the focus on coding regions.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize consequences on the primary/canonical transcript, which is vital for driver identification.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to see if these somatic variants have been previously recorded in other datasets (if available for zebrafish).
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Ensures the consequence calculation is driven by the appropriate Ensembl/GENCODE core annotation set.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, which is critical for assessing the impact on protein function.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard nomenclature for the amino acid changes, necessary for reporting and further study.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: A sequence-based tool to score splice site impacts, helping to identify non-synonymous effects that might arise from splicing changes.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is essential for mapping the exact location of the mutation in the coding sequence.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), allowing for direct link to protein-level functional analysis.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to make the output interpretable for biological prioritization.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Provides a sequence-based prediction of whether an amino acid substitution affects protein function (available for species with SIFT data).
✓ phenotypes [source: phenotypes, priority=recommended] confidence: medium
  Reason: Retrieves phenotype associations to help link variants to biological driver potential.
✗ clinvar [source: clinvar] confidence: high
  Reason: ClinVar data is human-only and not applicable to zebrafish.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is a human-specific integration tool.
✗ gnomad [source: af_gnomade] confidence: high
  Reason: gnomAD allele frequencies are human-only.
✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen is a human-only prediction tool.
✗ alphamissense [source: alphamissense] confidence: high
  Reason: AlphaMissense is restricted to human genomes.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --biotype --canonical --check_existing --core_type --domains --hgvs --maxentscan --numbers --protein --symbol --sift --plugin Phenotypes --plugin MaxEntScan
```
*Note: The `--plugin Phenotypes` and `--plugin MaxEntScan` require local installation of the respective plugin files and databases. On the Ensembl Web Interface, these can be enabled via the "Plugins" and "Additional Options" sections.*
