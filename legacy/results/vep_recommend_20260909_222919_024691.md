## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

### 2. Recommended Options
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Necessary to categorize the functional type of the impacted feature (e.g., protein_coding vs lincRNA), which is essential for a top-line summary.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Required as a dependency to retrieve population frequency data and clinical context.
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Standard practice to use Ensembl/GENCODE core annotations for reliable consequence calculation.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Crucial for structural variants/CNVs to determine if the gene is sensitive to changes in copy number (pHaplo).
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically requested to provide population frequency context for structural variants/CNVs using gnomAD SV data.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is part of a standard functional consequence summary.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Explicitly requested to capture disruptions to regulatory or non-coding elements.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides HGNC gene symbols, making the "top-line summary" human-readable and actionable.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps identify "the most reliable transcripts" by providing Transcript Support Level rankings.
✗ apprais [source: appris] confidence: high
  Reason: While useful, the user requested a "quick top-line summary" and did not specifically ask for isoform prioritization beyond transcript reliability.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is primarily used for single nucleotide variants/indels and is not prioritized for a structural variant summary.
✗ clinvar [source: clinvar] confidence: medium
  Reason: User requested population frequency context to distinguish somatic hits, but did not explicitly request clinical significance (pathogenicity) annotations.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is typically used for small variants and conflicts with the summary/most_severe output structure preferred for top-line views.
✗ most_severe [source: most_severe] confidence: medium
  Reason: While the user wants a summary, enabling --most_severe would disable the ability to see the regulatory/non-coding consequences requested.
✗ polyphen [source: polyphen] confidence: high
  Reason: Not applicable for structural variants/CNVs; these tools predict missense effect.

### 3. Generated VEP Command
```

```
