## User Query
I am looking at some human tumor sequencing results and I have noticed several large sections of DNA that seem to be either extra or missing. I am especially interested in the areas that don't actually make proteins but instead act as control switches for genes, as I want to see if these big changes might be affecting how those genes work and contributing to the cancer. It is also really important for me to know how common these same types of variations are in healthy people so I can tell the difference between normal variation and something potentially dangerous. How should I configure my run to get all that info about the regulatory impact and the population background?

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE annotation is the standard requirement for high-quality consequence calculation in human clinical studies.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for the user's focus on "control switches" (promoters, enhancers, etc.) within non-coding regions.

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs (extra or missing sections) to determine if the gene affected is sensitive to changes in copy number.

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Helps distinguish between rare, potentially deleterious variants and common variation by providing the loss-of-function observed/expected score.

✓ mastermind [source: mastermind, priority=recommended] confidence: high
  Reason: Directly supports the clinical interpretation goal by linking variants to existing medical literature evidence.

✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Provides phenotypic associations that aid in determining if a genomic change correlates with specific clinical outcomes.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most biologically relevant transcript for each gene when assessing the impact of a structural change.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Critical for identifying the nature of the regulatory features and non-coding elements being hit by the CNVs.

✓ cadd [source: cadd, priority=recommended] confidence: high
  Reason: Provides a combined pathogenicity score which is useful for assessing the functional impact of variations.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically addresses the user's need to know how common these "big changes" (structural variants) are in the healthy population.

✓ clinvar [source: check_existing, priority=recommended] confidence: high
  Reason: Essential for clinical interpretation to see if the detected variants have been previously reported as pathogenic in ClinVar.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for coding/missense variants; it is not applicable for structural-CNV analysis in this context.

✗ coding_only [source: coding_only] confidence: high
  Reason: User specifically requested focus on "areas that don't actually make proteins" (non-coding/regulatory).

✗ most_severe [source: most_severe] confidence: high
  Reason: Enabling this would conflict with several other useful plugins (CADD, etc.) and restrict the ability to see multiple consequences for non-coding regions.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: This plugin is designed for missense variants; it is not applicable to structural CNVs or regulatory regions.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --plugin DosageSensitivity --plugin Mastermind --plugin Phenotypes --plugin CADD --custom gnomad_sv,gnomad_sv.vcf.gz,exact --check_existing --regulatory --canonical --biotype
```
*Note: The `--custom` flag requires a local path to the gnomAD SV VCF file. On the Ensembl Web Interface, ensure "Regulatory" and "Dosage Sensitivity" are checked, and the gnomAD SV custom dataset is uploaded/selected.*
