## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation

- **species**: human (stated "human tumor-only")

- **variant_size_class**: structural-CNV (stated "structural variants and copy number alterations")
- **region_focus**: coding, regulatory-noncoding (stated "protein-coding regions... regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency (stated "functional consequences... context regarding population allele frequencies")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the default Ensembl/GENCODE annotation set which is the standard for human consequence calculation.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Essential for making results human-readable by adding HGNC gene symbols.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps identify the most reliable transcripts via Transcript Support Level (TSL) rankings.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Necessary to capture the requested impact on regulatory/non-coding elements (promoters, enhancers, etc.).
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps identify the primary transcript for each gene, satisfying the requirement for "most reliable transcripts."
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides context on whether a variant hits a protein-coding gene, lincRNA, etc., aiding consequence summary.
✓ loeuf [source: loeuF, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores which help assess the impact of variants based on gene constraint.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Critical for CNV/structural variant analysis to determine if a gene is sensitive to dosage changes (e.g., haploinsufficiency).
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically requested to distinguish somatic hits from common germline variation in the context of structural variants/CNVs.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is a fundamental part of "basic consequence" reporting.
✓ appris [source: appris, priority=recommended] confidence: medium
  Reason: Adds isoform annotation to help select functionally most important transcripts.
✓ most_severe [source: most_severe, priority=optional] confidence: medium
  Reason: Helpful for a "quick top-line summary" by condensing multiple consequences per variant, though it conflicts with many specific detail flags.
✗ hgvs [source: hgvs] confidence: high
  Reason: Not requested for this top-line summary and conflicts with --most_severe.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: User is analyzing structural variants; gnomAD exome frequencies are not appropriate for CNVs/SVs.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: Primarily for missense/SNV functional scores; not directly applicable to the primary goal of SV/CNV consequence.
✗ coding_only [source: coding_only] confidence: high
  Reason: User explicitly requested to capture regulatory and non-coding elements.
✗ pick [source: pick] confidence: high
  Reason: User wants a "summary" and "relevant information"; --pick might be too restrictive if they want to see the regulatory hits as well.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --symbol --tsl --regulatory --canonical --biotype --loeuf --dosage_sensitivity --custom gnomad_sv,custom_gnomad_sv.vcf,type=exact --numbers --appris --most_severe
```
*Note: The `--custom` flag for `gnomad_sv` requires a local path to the gnomAD SV VCF file. On the Ensembl web interface, you would select the 'Regulatory Build' and 'gnomAD SV' options in the configuration menu.*
