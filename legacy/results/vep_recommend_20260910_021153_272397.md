## User Query
I am working with human somatic whole exome sequencing data from a series of tumor biopsies and have identified several structural variants and copy number alterations that I need to interpret. Since I am still learning the ropes of setting up my annotation pipeline, I was wondering how I should approach this if my primary goal is just to get a quick top-line call on which protein-coding genes are being disrupted or lost by these large genomic changes, without necessarily needing an exhaustive breakdown of every small-scale nucleotide change at this stage.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default or Ensembl/GENCODE core annotation set is appropriate for a basic consequence analysis, and since the goal is gene disruption, core annotation is sufficient [source: core_type].

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Including the gene symbol is crucial for quick, top-line interpretation of disrupted genes, as requested [source: symbol].

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: This helps confirm that the affected regions are indeed protein-coding transcripts, which is fundamental when analyzing CNVs affecting genes [source: biotype].

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: For large structural changes, knowing the exon and intron numbering context provides necessary structural information, even if detailed consequence analysis is skipped [source: numbers].

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Since the input is structural variants (CNVs), the specialized plugin `gnomad_sv` is the definitive tool for annotating the structural variant allele frequencies, allowing filtering of common changes, which is best practice in clinical interpretation [source: gnomad_sv].

✗ hgvs [source: hgvs] confidence: medium
  Reason: While useful, HGVS nomenclature is more critical for point mutations or precise coding boundary calls. For a *quick top-line call* on large SVs, relying on the gene symbol and structural overlap might be sufficient overhead to avoid initially [source: hgvs].

✗ af_gnomade [source: af_gnomade] confidence: low
  Reason: This is for standard exome SNVs. For structural variants, `gnomad_sv` is the appropriate and specific resource to query for population frequency, making this redundant [source: gnomad_sv].

✗ most_severe [source: most_severe] confidence: medium
  Reason: The goal is a "quick top-line call" on *structural* changes. The `--most_severe` flag is designed to collapse consequences *per variant* (usually SNVs). For large CNVs, retaining transcript-level detail (which happens by default when not using summary) is better than collapsing it [source: most_severe].

✗ summary [source: summary] confidence: medium
  Reason: The summary format collapses all annotation details into a single field. Since the goal is to know *which genes* are disrupted, retaining the detailed, per-transcript annotation set is more informative for structural variants than a single summary field [source: summary].

✗ af_gnomadg [source: af_gnomadg] confidence: low
  Reason: This is for standard exome SNVs. For structural variants, `gnomad_sv` is the appropriate and specific resource to query for population frequency, making this redundant [source: gnomad_sv].
