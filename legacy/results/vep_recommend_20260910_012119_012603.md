## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

### 2. Recommended Options

✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: This sets the core annotation set. While the default is often fine, explicitly ensuring the best gene/transcript set is critical for structural/coding analysis, especially when including regulatory features.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: This is highly useful for both coding (e.g., distinguishing canonical vs pseudogene) and non-coding analysis, fulfilling the requirement to assess coding *and* non-coding elements.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides the essential gene context (HGNC symbol) needed for both clinical reporting and general summarization, satisfying the need for general context.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the need to capture "disruptions to regulatory or non-coding elements" by annotating overlaps with promoters/enhancers.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Since the input contains structural variants (CNV), this is the most appropriate plugin to annotate structural variations with population frequency data, allowing differentiation from common germline variation.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: When dealing with structural variants that may span introns or complex regions, knowing the precise exon/intron numbering (Number/Total) provides critical structural detail for basic consequence assessment.

✓ check_existing [source: check_existing, priority=optional] confidence: high
  Reason: This is crucial for assessing known co-located variants (dbSNP), providing immediate context on common germline variants that may overlap the novel structural hit.

✓ most_severe [source: most_severe, priority=optional] confidence: high
  Reason: Since the goal is a "quick top-line summary," using `--most_severe` (or possibly `--summary`) will collapse the results, preventing annotation explosion from overlapping transcripts while still providing a single, actionable consequence per region, which is efficient for large cohorts.

✗ hgvs [source: hgvs] confidence: medium
  Reason: While useful, HGVS is often very verbose for large structural variant cohorts, and the high-level summary goal suggests focusing on the functional impact plugins/annotations first.

✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: The more specific and structurally relevant `gnomad_sv` plugin is superior for structural variants, making general population frequency flags for single SNPs less useful in this context.

✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: Similar to above, `gnomad_sv` is the dedicated tool for structural variant frequency calling from gnomAD, making this general frequency flag redundant and less appropriate for SV analysis.

✗ cadd [source: cadd] confidence: high
  Reason: CADD is primarily designed for coding variants (missense/nonsense). For structural variants, the impact assessment is better covered by regulatory overlaps and gnomAD-SV frequencies, making this plugin overkill and potentially distracting for the "top-line summary" goal.

✗ sift [source: sift] confidence: high
  Reason: SIFT and other amino acid predictors (like PolyPhen) are only meaningful for point mutations within coding regions. Since the focus includes *structural* changes and *non-coding* changes, enabling these will produce many irrelevant or inapplicable results.

✗ polyphen [source: polyphen] confidence: high
  Reason: Similar to SIFT, this is a protein substitution predictor and is irrelevant for pure structural variants or non-coding regulatory elements.
