## User Query
I am analyzing somatic SNVs and indels from a mouse tumor WES to quickly identify any high-impact protein-coding variants.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (user specified "mouse")
- **origin**: somatic (user specified "somatic SNVs and indels from a mouse tumor")
- **variant_size_class**: small (user specified "SNVs and indels")
- **region_focus**: coding (user specified "protein-coding variants")
- **analysis_goal**: basic-consequence (user wants to "identify any high-impact... variants")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the Ensembl/GENCODE core annotation set is the standard for driving consequence calculations for non-human species.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: This is a human-only population frequency database.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard nomenclature for coding variants, which is essential for reporting protein-level changes. Note: This conflicts with `--most_severe`.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, which helps prioritize high-impact variants that disrupt functional sites.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output for easier biological interpretation. Note: This conflicts with `--most_severe`.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Identifies the canonical transcript, helping the user focus on the most biologically relevant isoform for the high-impact variant.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), crucial for linking SNVs/indels to protein-level consequences.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides the transcript biotype, allowing the user to confirm the variant is indeed in a protein-coding context.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Adds exon and intron numbering (e.g., 7/27), which is vital for describing the location of the variant within the coding sequence.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because the user needs detailed coding info (HGVS, symbols, domains). `--most_severe` would suppress these necessary descriptive fields.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Since the goal is specifically to identify "protein-coding variants," this restricts the output to relevant consequences, reducing noise.
✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Predicting whether a premature stop codon escapes nonsense-mediated decay is highly relevant for somatic "high-impact" analysis in tumors.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: This is a human-only meta-resource.
✗ clinvar [source: clinvar] confidence: high
  Reason: ClinVar is a human-only clinical database.

### 3. Generated VEP Command
```
vep --input_file tumor_variants.vcf --output_file somatic_analysis.txt --cache --symbol --hgvs --domains --canonical --protein --biotype --numbers --coding_only --plugin NMD
```
*Note: On the Ensembl Web Interface, select "Mouse" as the species, check "Gene Symbol", "HGVS nomenclature", "Protein ID", "Transcript biotype", "Canonical transcript", "Exon/Intron numbering", and "Protein domains". For the NMD plugin, you may need to use the command line version if not available in the web UI.*
