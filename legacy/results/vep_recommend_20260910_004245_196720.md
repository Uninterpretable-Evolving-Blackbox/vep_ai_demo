## User Query
I am looking at some human tumor sequencing results and I have noticed several large sections of DNA that seem to be either extra or missing. I am especially interested in the areas that don't actually make proteins but instead act as control switches for genes, as I want to see if these big changes might be affecting how those genes work and contributing to the cancer. It is also really important for me to know how common these same types of variations are in healthy people so I can tell the difference between normal variation and something potentially dangerous. How should I configure my run to get all that info about the regulatory impact and the population background?

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard requirement for high-quality human clinical interpretation.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for coding variants; for large CNVs and regulatory regions, it is less relevant to this specific focus.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: This provides exome-only frequencies; for structural variants and regulatory regions, genome-based data is more appropriate.
✗ tsl [source: tsl] confidence: high
  Reason: Transcript Support Level is a metric for transcript quality, which is not the primary focus of CNV/regulatory analysis.
✗ domains [source: domains] confidence: high
  Reason: Protein domain annotation is not applicable to non-coding regulatory regions.
✗ frequency [source: frequency] confidence: high
  Reason: This is for pre-filtering variants by frequency, which might hide rare but clinically significant structural variants.
✗ most_severe [source: most_severe] confidence: high
  Reason: This flag restricts output to a single consequence, which would hide the complex overlapping effects common in regulatory/CNV analysis.
✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Helps assess the impact of variants relative to the observed constraint in the population, useful for interpreting clinical significance.
✓ mastermind [source: mastermind, priority=recommended] confidence: high
  Reason: Directly addresses the clinical interpretation goal by linking variants to medical literature.
✗ symbol [source: symbol] confidence: high
  Reason: Conflicts with --most_severe; while useful, the priority here is on regulatory/structural impact rather than simple gene labeling.
✓ check_existing [source: check_existing, priority=optional] confidence: high
  Reason: Required to enable the retrieval of known variants and ClinVar data to differentiate between normal and dangerous variations.
✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: While genome data is good, the specific requirement for structural variants is best met by the dedicated SV custom dataset.
✗ appris [source: appris] confidence: high
  Reason: APPRIS focuses on isoform selection for coding transcripts, which is not the priority for non-coding regulatory regions.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the goal of identifying "control switches" (enhancers, promoters, etc.) in non-coding regions.
✗ coding_only [source: coding_only] confidence: high
  Reason: This would exclude the user's primary region of interest (regulatory-noncoding).
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs, as it provides information on whether a gene is sensitive to changes in copy number.
✓ clinvar [source: clinvar, priority=recommended] confidence: high
  Reason: Essential for clinical interpretation to see if the identified regions/variants are already documented as pathogenic.
✗ mane [source: mane] confidence: high
  Reason: MANE is designed to standardize coding transcript selection; not the priority for regulatory/structural analysis.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps identify the nature of the regulatory features or non-coding transcripts being hit by the CNV.
✓ cadd [source: cadd, priority=recommended] confidence: high
  Reason: Provides a combined score for deleteriousness, which can be useful for assessing the impact of non-coding changes.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically addresses the requirement to know how common these "large sections" (structural variants) are in the healthy population.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Links the genomic changes to known phenotypic/disease associations, aiding clinical interpretation.

### 3. Generated VEP Command
```
vep --input_file tumor_variants.vcf --output_file results.txt --cache --plugin ClinVar --plugin Mastermind --plugin DosageSensitivity --plugin CADD --plugin Phenotypes --plugin LOEUF --regulatory --biotype --check_existing --custom gnomad_sv,gnomAD_SV_VCF,type=exact,overlap_cutoff=exact
```
*Note: The `--custom` flag requires the path to the gnomAD SV VCF file. The `--plugin` arguments for ClinVar and Mastermind typically require their respective data files to be present in the plugin directory. On the Ensembl Web Interface, enable "Regulatory" under the "Additional Annotation" section and select "ClinVar" and "Mastermind" from the plugin list.*
