## User Query
I’m working through some human tumour sequencing data where we're specifically looking for large-scale changes in the DNA structure, like deletions or duplications. A lot of these structural changes are landing in the regions outside of the actual genes, so I need a way to quickly figure out if these stretches of missing or extra DNA might be affecting how genes are turned on or off. It would also be really helpful to see how common these types of variations are in the general healthy population so I can better judge whether a finding looks like a potential driver for the cancer or just a common variation.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: This is the default and necessary annotation set for basic gene/transcript context calculation, required for structural variant analysis across different features.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: This is critical because the analysis focuses on structural changes in non-coding/regulatory regions (enhancers, promoters). This plugin explicitly annotates overlaps with these functional elements.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: The goal is to compare findings to the general healthy population, and this plugin is specifically designed to annotate structural variants (SV) with gnomAD allele frequencies, allowing you to filter common benign variants.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Since the variants are targeting non-coding regions, knowing the general biological nature of the affected transcript/region (e.g., lincRNA, promoter) is essential for interpretation.

✗ hgvs [source: hgvs] confidence: medium
  Reason: While providing standard nomenclature is generally useful, HGVS conversion adds complexity and is often better handled post-processing, especially with structural variants where nomenclature can be challenging.

✗ af_gnomade [source: af_gnomade] confidence: low
  Reason: While population frequency is key, gnomAD-specific structural variation frequencies are best captured by `--gnomad_sv`. Using the standard `--af_gnomade` is intended for single-nucleotide variants, not large SVs.

✗ af_gnomadg [source: af_gnomadg] confidence: low
  Reason: This is analogous to `--af_gnomade` and is less targeted for structural variation frequency assessment than the dedicated `--gnomad_sv` plugin.

✗ most_severe [source: most_severe] confidence: high
  Reason: This option restricts output to a single consequence type per variant. For structural variants, retaining detailed annotations across all overlapping transcripts/features is far more informative than collapsing to the single "most severe" prediction.

✗ summary [source: summary] confidence: high
  Reason: Similar to `--most_severe`, this collapses the output. For structural variants interacting with multiple regulatory elements or overlapping multiple genes, retaining the full, detailed annotation set is necessary for comprehensive reporting.

✗ af [source: af] confidence: high
  Reason: This plugin is primarily for known short variants. Given the focus is on large structural changes, `--gnomad_sv` is a much more appropriate and specific choice for population frequency estimation.

✗ tsl [source: tsl] confidence: medium
  Reason: Transcript Support Level (TSL) is most relevant for coding variants to gauge transcript reliability. For SVs targeting regulatory regions, the primary functional annotation (`regulatory`) is more important than the transcript support level.

✗ domains [source: domains] confidence: high
  Reason: The focus is on regulatory and structural disruptions, not protein domains. Therefore, this option is not applicable and should be left disabled to keep the output clean.
