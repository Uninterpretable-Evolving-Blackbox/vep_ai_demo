## User Query
I am working on a new project involving whole genome sequencing data from a large cohort of wild-type *Mus musculus* and I am trying to figure out how to properly set up my annotation pipeline. We have identified many germline SNVs and small indels, but since my research focuses specifically on the impact of variants in non-coding and regulatory regions like enhancers, I am struggling with the configuration. My goal is just to get a quick top-line assessment of whether these small variants fall within functional non-coding elements or have predicted effects in those areas.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is recommended for standard consequence calculation in non-human species.
✗ hgvs [source: hgvs] confidence: high
  Reason: While useful, it is an optional add-on that can conflict with summary/most_severe flags; not required for a "top-line" non-coding assessment.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the user's focus on enhancers and non-coding functional elements by overlapping with Ensembl's Regulatory Build.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for identifying the type of non-coding feature (e.g., lincRNA, miRNA, or regulatory element) being hit.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize consequences by identifying the canonical transcript, providing a stable reference point for the assessment.
✗ most_severe [source: most_severe] confidence: medium
  Reason: Disabled to avoid conflicts with other descriptive flags; for non-coding studies, seeing all overlapping regulatory features is often more informative than a single "most severe" term.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; this is a human-only resource for missense variants.
✗ af_gnomad [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only database.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only clinical database.
✓ check_existing [source: check_existing] confidence: medium
  Reason: Recommended to see if these wild-type SNVs have been previously recorded in existing variation databases for *Mus musculus*.
✗ cell_type [source: cell_type] confidence: medium
  Reason: Though it works with `--regulatory`, it requires specific cell-type epigenome data which the user has not provided/requested for this "top-line" assessment.

### 3. Generated VEP Command
```
vep --input_file input.vcf --output_file output.txt --cache --species mus_musculus --regulatory --biotype --canonical --check_existing
```
*Note: The `--regulatory` flag significantly increases processing time as it performs spatial overlaps with regulatory builds. In the Ensembl Web Interface, ensure "Regulatory" is checked under the "Extra" or "Annotation" sections.*
