## User Query
I have germline Mus musculus WES data; I need to identify protein-altering SNVs and indels in coding regions and assess their predicted functional pathogenicity.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (*Mus musculus* mentioned)
- **origin**: germline (explicitly stated)
- **variant_size_class**: small (SNVs and indels)
- **region_focus**: coding (explicitly stated)
- **analysis_goal**: clinical-interpretation (identifying functional pathogenicity for potential biological/clinical relevance)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential to drive consequence calculation using the Ensembl/GENCODE core annotation set.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, which is essential for identifying the affected genes in Mus musculus.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides HGVS nomenclature for the variants, which is necessary for standardizing reporting of protein-altering changes.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP) to link variants to protein-level consequences.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps confirm the transcript type (e.g., protein_coding) to ensure the focus remains on coding regions.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Identifies the canonical transcript, helping to prioritize the most likely functional consequence.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information (Pfam, etc.), which is critical for assessing if a variant disrupts a functional site.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: SIFT is available for species with variation data like mouse and provides a sequence-based prediction of amino acid substitution impact.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Essential for assessing the impact of indels/variants on splice sites, even within coding-focused studies.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon and intron numbering, helping to localize the variant within the gene structure.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Retrieves phenotype associations for genes, aiding in the interpretation of the variant's functional relevance.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Optional but helpful to see if the variant has been previously cataloged in mouse variation databases.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Since the goal is specifically to identify protein-altering changes, this restricts output to coding regions to reduce noise.
✗ most_severe [source: most_severe] confidence: high
  Reason: Conflicts with hgvs, symbol, and sift; for functional interpretation, you need the full transcript details, not a collapsed single term.
✗ summary [source: summary] confidence: high
  Reason: Conflicts with hgvs, symbol, and sift; summary mode hides the detailed annotations required for pathogenicity assessment.
✗ clinvar [source: clinvar] confidence: high
  Reason: ClinVar is a human-only resource.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: gnomAD is a human-only resource.
✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen is a human-only tool.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is a human-only tool.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is a human-only resource.

### 3. Generated VEP Command
```
vep --input_file input.vcf --output_file output.txt --cache --format vcf --vcf --coding_only --symbol --hgvs --protein --biotype --canonical --domains --sift --maxentscan --numbers --phenotypes --check_existing
```
*Note: When using plugins like `--phenotypes` or `--domains`, ensure the corresponding plugin cache files are installed. On the Ensembl Web Interface, these correspond to selecting the respective checkboxes in the "Plugins" and "Output" sections.*
