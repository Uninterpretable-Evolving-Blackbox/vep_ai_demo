## User Query
I am working with human somatic whole exome sequencing data from a series of tumor biopsies and have identified several structural variants and copy number alterations that I need to interpret. Since I am still learning the ropes of setting up my annotation pipeline, I was wondering how I should approach this if my primary goal is just to get a quick top-line call on which protein-coding genes are being disrupted or lost by these large genomic changes, without necessarily needing an exhaustive breakdown of every small-scale nucleotide change at this stage.

### 2. Recommended Options
✓ **core_type** [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is recommended for human species to ensure standard consequence calculation.
✗ **hgvs** [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily for small-scale nucleotide changes; the user wants to avoid exhaustive small-scale detail.
✓ **tsl** [source: tsl, priority=recommended] confidence: high
  Reason: Transcript Support Level helps prioritize high-confidence transcripts, which is useful when assessing gene disruption.
✓ **loeuf** [source: loeuf, priority=recommended] confidence: high
  Reason: gnomAD LOEUF scores help determine if the disrupted gene is intolerant to loss-of-function, aiding interpretation of CNVs.
✓ **symbol** [source: symbol, priority=recommended] confidence: high
  Reason: Adding HGNC gene symbols makes the "top-line call" on which genes are disrupted much more human-readable.
✗ **most_severe** [source: most_severe] confidence: medium
  Reason: While the user wants a "top-line call," enabling `--most_severe` conflicts with several other useful descriptive options like `--symbol`.
✓ **dosage_sensitivity** [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: This is critical for CNV/Structural Variant analysis, as it identifies if the gene is sensitive to changes in copy number (e.g., haploinsufficiency).
✓ **canonical** [source: canonical, priority=recommended] confidence: high
  Reason: Helps identify the primary transcript affected by the structural change.
✓ **biotype** [source: biotype, priority=recommended] confidence: high
  Reason: Essential to confirm the biotype of the disrupted feature (e.g., protein_coding) to meet the user's coding focus.
✓ **gnomad_sv** [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically designed to annotate structural variants using gnomAD SV allele frequencies, which is the user's primary variant class.
✓ **numbers** [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to help localize where the disruption occurs within the gene.
✗ **dbnsfp** [source: dbnsfp] confidence: high
  Reason: This plugin is for missense (SNV) scoring; it is not applicable for large-scale structural/CNV variants.
✗ **sift** [source: sift] confidence: high
  Reason: SIFT is for single nucleotide missense variants and is not applicable to structural variants or CNVs.
✗ **polyphen** [source: polyphen] confidence: high
  Reason: PolyPhen is for missense variants and provides no value for CNV/SV interpretation.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --symbol --tsl --canonical --biotype --numbers --loeuf --dosage_sensitivity --custom gnomad_sv,gnomad_sv.vcf.gz,exact
```
*Note: The `--custom` flag requires a path to a gnomAD SV VCF file. On the Ensembl Web Interface, these options correspond to checking the boxes for Gene Symbol, Transcript Support Level, Canonical, Biotype, Exon/Intron numbering, LOEUF, Dosage Sensitivity, and the gnomAD SV custom dataset.*
