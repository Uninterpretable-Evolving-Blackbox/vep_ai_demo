## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Necessary to drive the primary consequence calculation using Ensembl/GENCODE annotations.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Essential for human-readable results by adding gene symbols (e.g., BRCA1).
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides context on whether the affected feature is protein-coding, lincRNA, etc., which is critical for structural variant interpretation.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps identify impacts on the most reliable/representative transcripts for coding regions.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Required to capture potential disruptions to promoters, enhancers, and other regulatory elements as requested.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically designed to annotate structural variants with gnomAD SV allele frequencies to distinguish somatic hits from common germline CNVs.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Provides per-gene dosage sensitivity scores (e.g., pHaplo), which is vital for interpreting the impact of CNVs/structural variants.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to help localize the boundaries of structural disruptions.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Adds Transcript Support Level to help the user identify the most well-supported transcripts.
✗ most_severe [source: most_severe] confidence: high
  Reason: The user requested a "top-line summary," but also wants to capture "any potential disruptions" to regulatory elements. Using `--most_severe` would collapse the results to one term, potentially hiding the regulatory consequences if a coding consequence is also present.
✗ summary [source: summary] confidence: high
  Reason: While the user asked for a "summary," in VEP terms, `--summary` collapses all information into a single line per variant, which would prevent seeing both the coding and regulatory consequences requested.
✗ sift [source: sift] confidence: high
  Reason: Missense predictors like SIFT are not applicable to structural variants or CNVs.
✗ polyphen [source: polyphen] confidence: high
  Reason: Missense predictors like PolyPhen are not applicable to structural variants or CNVs.
✗ cadd [source: cadd] confidence: high
  Reason: Missense/indel predictors like CADD are not applicable to structural variants.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --everything --symbol --biotype --canonical --regulatory --gnomad_sv <path_to_gnomad_sv.vcf.gz> --plugin DosageSensitivity --numbers --tsl
```
*Note: The `--everything` flag is a shorthand that includes many features, but for a strict pipeline, it is better to explicitly list the flags above. On the Ensembl Web Interface, ensure you select "Regulatory" and "Structural Variant" specific frequency datasets.*
