## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation
### 1. Detected Scenario
- **species**: human ("human tumor-only...")
- **origin**: somatic ("tumor-only... somatic hits")
- **variant_size_class**: structural-CNV ("structural variants and copy number alterations")
- **region_focus**: coding, regulatory-noncoding ("affect protein-coding regions... disruptions to regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency ("top-line summary of their functional consequences... context regarding population allele frequencies")

### 2. Recommended Options
✓ appellis [source: appris, priority=recommended] confidence: high
  Reason: Helps identify principal isoforms, which is useful when assessing the impact of structural changes on the most functionally relevant transcripts.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for categorizing the impact of variants on different genomic features (e.g., protein_coding vs lincRNA).
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps the user identify the primary transcript for each gene, supporting the goal of identifying impacts on the "most reliable" transcripts.
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the standard Ensembl/GENCODE annotation set to drive consequence calculation.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs and structural variants to assess the impact of gene dosage changes.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically provides allele frequencies for structural variants from gnomAD, addressing the user's need for population frequency context.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which aids in the "top-line summary" of where a structural change falls within a gene.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Enables the detection of overlaps with regulatory regions (promoters, enhancers), satisfying the non-coding focus.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds HGNC gene symbols to make the output human-readable and useful for quick functional summaries.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Adds Transcript Support Level to help the user prioritize more reliable/well-supported transcripts.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: This specific flag is for exome-only frequencies; for structural variants, gnomad_sv is the preferred recommendation.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is a missense/small-variant predictor and is not applicable for structural-CNV analysis.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP aggregates data for small variants (SNVs/indels) and is not applicable for structural-CNV.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature in this context is primarily for small variants and conflicts with several other summary/severity flags.
✗ most_severe [source: most_severe] confidence: high
  Reason: The user wants a summary of consequences, and --most_severe often conflicts with the detailed transcript information (symbol, tsl) requested.
✗ pick [source: pick] confidence: high
  Reason: The user wants to see how changes affect regions (plural); --pick restricts to one consequence per variant, which might hide regulatory impacts if a coding impact is also present.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --symbol --biotype --canonical --tsl --appris --regulatory --dosage_sensitivity --gnomad_sv --numbers
```
*(Note: On the Ensembl Web Interface, ensure you select the "Regulatory" and "Dosage Sensitivity" plugins and check the "gnomAD SV" frequency option.)*
