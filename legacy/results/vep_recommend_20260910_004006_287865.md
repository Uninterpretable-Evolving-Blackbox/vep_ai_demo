## User Query
I’m working through some human tumour sequencing data where we're specifically looking for large-scale changes in the DNA structure, like deletions or duplications. A lot of these structural changes are landing in the regions outside of the actual genes, so I need a way to quickly figure out if these stretches of missing or extra DNA might be affecting how genes are turned on or off. It would also be really helpful to see how common these types of variations are in the general healthy population so I can better judge whether a finding looks like a potential driver for the cancer or just a common variation.

- **region_focus**: regulatory-noncoding (User specifies "regions outside of the actual genes... affecting how genes are turned on or off")
- **analysis_goal**: clinical-interpretation, population-frequency (User mentions judging findings as "potential driver" vs "common variation in the general healthy population")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core is the standard approach for human clinical analysis.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the need to see if structural changes affect gene regulation (promoters, enhancers, etc.).

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Essential for CNVs (deletions/duplications) to assess if the affected genes are sensitive to changes in copy number (pHaplo/pCNV).

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish the nature of the affected genomic features in non-coding regions.

✓ cadd [source: cadd, priority=recommended] confidence: high
  Reason: Provides a combined deleteriousness score to help prioritize variants for clinical interpretation.

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores to help assess the evolutionary constraint of the affected genes.

✓ mastermind [source: mastermind, priority=recommended] confidence: high
  Reason: Links variants to clinical evidence in medical literature, aiding in clinical interpretation.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically provides allele frequencies for structural variants from gnomAD, fulfilling the requirement to check population frequency for CNVs.

✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Helps link findings to known disease phenotypes, aiding clinical driver identification.

✓ clinvar [source: clinvar, priority=recommended] confidence: high
  Reason: Provides known clinical significance from ClinVar, vital for distinguishing drivers from common variants.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Necessary to enable ClinVar and population frequency lookups by identifying known variants at the coordinates.

✓ pubmed [source: pubmed, priority=optional] confidence: medium
  Reason: Provides supporting literature for clinical interpretation.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for small variants (SNVs/Indels); for large CNVs, it is not applicable in this context.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: This plugin is optimized for missense variants; it is not applicable for structural/CNV analysis.

✗ coding_only [source: coding_only] confidence: high
  Reason: The user specifically wants to focus on non-coding/regulatory regions; this would hide the target data.

✗ most_severe [source: most_severe] confidence: high
  Reason: This flag conflicts with several useful annotation plugins and would restrict the detailed regulatory output required.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --plugin DosageSensitivity --plugin CADD --plugin LOEUF --plugin Mastermind --plugin Phenotypes --check_existing --plugin ClinVar --plugin PubMed --regulatory --biotype --custom gnomad_sv,gnomad_sv.vcf.gz,type=exact,overlap_cutoff=exact
```
*Note: For the web interface, ensure "Regulatory" and "Dosage Sensitivity" are selected, and upload the gnomAD SV file as a custom annotation if using the local cache.*
