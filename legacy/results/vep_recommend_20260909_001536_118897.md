**Date:** 2026-09-09T00:15:36.119820

## User Query
I am currently working through some sequencing results from a mouse model of cancer and I need to figure out how to properly annotate the list of changes we've identified in the tumor tissue. We are looking at single letter changes as well as small additions or removals of DNA, and it is really important for my analysis that I can see both the impact on protein-coding sequences and any potential effects on the control regions surrounding the genes. Ultimately, I need to be able to tell which of these changes look like they might actually be driving the tumor progression.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (user specifies "mouse model")
- **origin**: somatic (user specifies "changes we've identified in the tumor tissue")
- **variant_size_class**: small (user specifies "single letter changes as well as small additions or removals")
- **region_focus**: coding, regulatory-noncoding (user specifies "impact on protein-coding sequences and any potential effects on the control regions")
- **analysis_goal**: clinical-interpretation (user specifies "tell which of these changes look like they might actually be driving the tumor progression")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the Ensembl/GENCODE core annotation set is the standard for driving consequence calculations in non-human species.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides HGVS nomenclature which is essential for standardizing the description of the variants identified in the tumor.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Helps interpret the impact on protein function by identifying if variants overlap known protein domains.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to make the results interpretable for biological/clinical context.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Necessary to address the user's requirement to look at "control regions surrounding the genes" (promoters, enhancers, etc.).
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Assists in clinical-style interpretation by linking genes to known phenotype associations.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most likely functional transcript for each gene.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Provides Ensembl protein identifiers (ENSP) to link coding changes to protein-level consequences.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Distinguishes between protein-coding genes and other features like lincRNA or regulatory elements.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Provides sequence-based scoring for splice site impact, which is critical for evaluating small indels/SNVs.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to help precisely locate the variant within the gene structure.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Provides a prediction of whether a missense substitution affects protein function for species with available SIFT data (like mouse).
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Recommended to see if the somatic changes overlap with any known variation in the mouse genome.
✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Helps determine if a premature stop codon will trigger nonsense-mediated decay, a key driver in cancer.
✓ uniprot [source: uniprot, priority=optional] confidence: medium
  Reason: Useful for cross-referencing protein-level changes with established functional databases.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because it conflicts with several recommended options required for detailed functional interpretation (hgvs, symbol, sift, etc.).
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE; gnomAD is human-only.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar data is human-only.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is human-only.

### 3. Generated VEP Command
```
vep --input_file tumor_variants.vcf --output_file annotated_tumor_variants.txt --cache --format vcf --vcf --hgvs --domains --symbol --regulatory --canonical --protein --biotype --maxentscan --numbers --sift --check_existing --plugin NMD --plugin UniProt
```
*Note: On the Ensembl Web Interface, ensure you select "Mouse" as the species and enable the "Regulatory" and "Protein" checkboxes. The `--plugin` flags for NMD and UniProt may need to be added via the 'Custom Plugins' section.*
