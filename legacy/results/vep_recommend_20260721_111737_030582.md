## User Query
somatic point mutations from a mouse tumour

## Recommendation
### 1. Detected Use Case
**Category:** `somatic_cancer` and `non_human`
**Reason:** The objective is to identify driver mutations in a tumor (somatic analysis), but the subject is a mouse (*Mus musculus*). This requires a hybrid approach: prioritizing tools used for somatic cancer discovery while strictly disabling all human-only databases and prediction algorithms.

### 2. Recommended Options
✓ transcript_set [source: core_type, priority=critical] confidence: high
  Reason: Using the default Ensembl/GENCODE set is preferred for mouse as RefSeq coverage can be inconsistent.

✗ mane_select [source: mane] confidence: high
  Reason: MANE Select is a human-only feature (NCBI/EBI collaboration).

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: In the absence of MANE for mouse, selecting the canonical transcript is the best way to standardize results.

✗ pick [source: pick] confidence: high
  Reason: For driver identification, it is important to see all transcripts that may be affected by the mutation rather than just one line per variant.

✗ per_gene [source: per_gene] confidence: high
  Reason: Restricting to one consequence per gene might hide isoform-specific functional impacts which are relevant for characterizing tumor drivers.

✗ most_severe [source: most_severe] confidence: high
  Reason: Disabling this allows the output of detailed annotations (SIFT, Domains) which are necessary for interpreting impact beyond a simple severity ranking. This also avoids conflicts with SIFT and Domains.

✗ summary [source: summary] confidence: high
  Reason: Summary mode strips away essential details needed to evaluate the biological consequence of specific mutations.

✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Essential for providing standardized nomenclature that can be used to communicate findings in experimental reports.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Converts Ensembl IDs to mouse gene symbols (e.g., *Tp53*), making the results human-readable and easier to cross-reference with literature.

✓ protein [source: protein, priority=optional] confidence: medium
  Reason: Providing ENSP identifiers is useful for linking mutations to downstream protein structure analysis.

✓ sift [source: sift, priority=recommended] confidence: high
  Reason: SIFT is species-compatible and provides a predictive score for the impact of amino acid substitutions in mouse proteins.

✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen-2 is a human-only tool and will not function on mouse data.

✗ cadd [source: cadd] confidence: high
  Reason: CADD is trained specifically on human genomic datasets and is not applicable to mouse.

✗ alphamissense [source: alphamissense] confidence: high
  Reason: AlphaMissense predictions are currently restricted to human (GRCh37/38).

✗ revel [source: revel] confidence: high
  Reason: REVEL is an ensemble method trained on human variant data and is not applicable to mouse.

✗ clinvar [source: clinvar] confidence: high
  Reason: ClinVar contains human clinical significance data; applying it to mouse variants would be inappropriate.

✓ check_existing [source: check_existing, priority=critical] confidence: high
  Reason: Essential to identify if the somatic mutation overlaps with previously reported mouse variants in databases like MGI or Ensembl.

✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Crucial for cancer analysis to determine if a mutation falls within a known functional protein domain (e.g., kinase domain).

✓ biotype [source: biotype, priority=recommended] confidence: medium
  Reason: Provides context on whether the variant hits a protein-coding gene or a non-coding feature like lincRNA.

✓ transcript_version [source: transcript_version, priority=recommended] confidence: high
  Reason: Ensures reproducibility by linking results to specific versions of the mouse transcripts.

### 3. Generated VEP Command
```bash
vep --input_file tumor_samples.vcf \
    --output_file annotations.txt \
    --cache \
    --dir_cache /path/to/vep_cache \
    --species mus_musculus \
    --hgvs \
    --symbol \
    --protein \
    --sift b \
    --domains \
    --check_existing \
    --biotype \
    --transcript_version
```
*Note: If using the Ensembl Web Interface, ensure you select "Mus musculus" from the species dropdown and manually check the boxes for HGVS, Symbol, Protein, SIFT, Domains, and Check existing variants.*
