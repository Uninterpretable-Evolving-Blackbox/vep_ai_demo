# VEP Recommendation

**Date:** 2026-09-10T00:29:20.977064

## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation

- **species**: human (explicitly stated "human tumor-only")
- **origin**: somatic (implied by "tumor-only" and "distinguish these somatic hits from common germline variation")
- **variant_size_class**: structural-CNV (explicitly stated "structural variants and copy number alterations")
- **region_focus**: coding, regulatory-noncoding (explicitly stated "protein-coding regions" and "disruptions to regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency (requested "top-line summary of functional consequences" and "context regarding population allele frequencies")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core is recommended for high-quality consequence calculation in humans.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Essential for human analysis to provide HGNC gene symbols for easy interpretation.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps identify the most reliable transcripts by providing Transcript Support Level.
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Provides APPRIS isoform annotation to help prioritize functionally important transcripts.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the need to capture disruptions to regulatory and non-coding elements.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Crucial for CNVs as it provides gene dosage sensitivity scores (e.g., pHaplo).
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between protein-coding and non-coding/regulatory features.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to give a "top-line summary" of the structural impact.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically requested to distinguish somatic hits from germline variation using gnomAD structural variant frequencies.
✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores to help assess the constraint/essentiality of genes hit by CNVs.
✗ hgvs [source: hgvs] confidence: high
  Reason: Conflicts with the goal of a "quick top-line summary" and will increase output complexity; more useful for single nucleotide variants than large CNVs.
✗ most_severe [source: most_severe] confidence: medium
  Reason: While useful for a summary, it conflicts with several recommended annotation flags like `symbol` and `tsl`.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: Primarily for missense single nucleotide variants; not applicable for structural-CNV analysis.
✗ spliceai [source: spliceai] confidence: high
  Reason: Not applicable for the primary focus on structural/CNV variants.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --symbol --tsl --appris --regulatory --dosage_sensitivity --biotype --numbers --custom gnomad_sv,gnomad_sv.vcf.gz,exact --plugin LOEUF
```
*Note: The `--custom` flag requires a local path to the gnomAD SV VCF file. On the Ensembl Web Interface, these correspond to selecting the "Regulatory" and "gnomAD SV" options in the configuration menu.*
