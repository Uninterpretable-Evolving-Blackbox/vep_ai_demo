## User Query
I am analyzing somatic SNVs and indels from a zebrafish tumor model and need to quickly identify any variants that potentially impact regulatory or non-coding elements.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (Zebrafish/Danio rerio)
- **origin**: somatic (tumor model)
- **variant_size_class**: small (SNVs and indels)
- **region_focus**: regulatory-noncoding (impact on regulatory/non-coding elements)
- **analysis_goal**: basic-consequence (identifying potential impact)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the standard Ensembl/GENCODE core annotation to drive consequence calculation, which is the standard for non-human species.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Specifically requested to identify impacts on regulatory regions (promoters, enhancers, etc.) for the species.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most biologically relevant transcript for consequence calculation.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for non-coding analysis to distinguish between different types of non-coding features (e.g., lincRNA, miRNA).

✗ hgvs [source: hgvs, priority=optional] confidence: medium
  Reason: While helpful, HGVS nomenclature is often more standardized for human clinical reporting; for a basic non-human somatic screen, it is not strictly required for initial identification.

✗ most_severe [source: most_severe, priority=optional] confidence: high
  Reason: Disabled because it conflicts with several other useful annotation options and the user wants to "identify" variants, not just the single most severe term.

✗ af_gnomad [source: af_gnomade, priority=NOT APPLICABLE] confidence: high
  Reason: gnomAD is a human-only database.

✗ dbnsfp [source: dbnsfp, priority=NOT APPLICABLE] confidence: high
  Reason: dbNSFP is a human-only meta-resource.

✗ clinvar [source: clinvar, priority=NOT APPLICABLE] confidence: high
  Reason: ClinVar is a human clinical database.

✗ cadd [source: cadd, priority=NOT APPLICABLE] confidence: high
  Reason: CADD scores are human-only.

### 3. Generated VEP Command
```
vep --input_file zebrafish_somatic_variants.vcf --output_file zebrafish_consequences.txt --cache --format vcf --assembly danRer11 --regulatory --canonical --biotype
```
*Note: `--assembly` should be adjusted to your specific zebrafish genome version (e.g., danRer11). In the Ensembl Web Interface, select 'Regulatory' and 'Biotype' under the optional settings/annotations section.*
