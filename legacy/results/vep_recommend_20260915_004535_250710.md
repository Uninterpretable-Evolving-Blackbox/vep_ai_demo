## User Query
I’m working through some human tumour sequencing data where we're specifically looking for large-scale changes in the DNA structure, like deletions or duplications. A lot of these structural changes are landing in the regions outside of the actual genes, so I need a way to quickly figure out if these stretches of missing or extra DNA might be affecting how genes are turned on or off. It would also be really helpful to see how common these types of variations are in the general healthy population so I can better judge whether a finding looks like a potential driver for the cancer or just a common variation.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard and recommended approach for human variant consequence calculation.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for the user's goal of determining if non-coding structural changes affect gene regulation (promoters, enhancers, etc.).

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Crucial for CNVs (deletions/duplications) to identify if the affected genes are sensitive to changes in copy number (e.g., pHaplo).

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores, which help assess the impact of loss-of-function/structural changes in the context of evolutionary constraint.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most reliable transcript for consequence mapping when evaluating the impact of a structural change.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides context on the nature of the features being hit (e.g., lincRNA, protein_coding), which is vital for non-coding analysis.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically addresses the user's need to compare structural variants against population-scale structural variation frequencies in gnomAD.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Allows the identification of known variants co-located with the CNVs, helping distinguish known common variants from novel findings.

✓ clinvar [source: clinvar, priority=optional] confidence: medium
  Reason: Provides clinical significance for co-located variants, aiding in the distinction between drivers and common benign variations.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily focused on coding/small variant changes and is not applicable/helpful for large-scale structural CNVs in this context.

✗ coding_only [source: coding_only] confidence: high
  Reason: The user explicitly wants to focus on regions "outside of the actual genes" (non-coding/regulatory); enabling this would hide the most relevant data.

✗ most_severe [source: most_severe] confidence: high
  Reason: This flag restricts output to a single term, which would likely hide the regulatory/non-coding consequences the user is specifically looking for.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is a resource for missense (single nucleotide) variants; it does not provide information relevant to structural CNVs or regulatory regions.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --regulatory --dosage_sensitivity --loeuf --canonical --biotype --custom gnomad_sv,gnomad_sv.vcf.gz,exact --check_existing --clinvar
```
*(Note: The `--custom` flag requires a local path to the gnomAD SV VCF file. On the Ensembl Web Interface, these are selected via the 'Custom Datasets' and 'Plugins' sections.)*
