## User Query
I am currently working through some sequencing results from a mouse model of cancer and I need to figure out how to properly annotate the list of changes we've identified in the tumor tissue. We are looking at single letter changes as well as small additions or removals of DNA, and it is really important for my analysis that I can see both the impact on protein-coding sequences and any potential effects on the control regions surrounding the genes. Ultimately, I need to be able to tell which of these changes look like they might actually be driving the tumor progression.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (mouse model)
- **origin**: somatic (tumor tissue)
- **variant_size_class**: small (single letter changes and small additions/removals)
- **region_focus**: coding, regulatory-noncoding (impact on protein-coding and control regions)
- **analysis_goal**: clinical-interpretation (identifying potential drivers of tumor progression)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential to define the transcript/gene annotation set driving the consequence calculation.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, which is critical for identifying driver genes in a cancer model.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standardized nomenclature for both coding and non-coding changes, essential for reporting.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Directly addresses the need to identify effects on control regions (promoters, enhancers, etc.).
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between protein-coding and regulatory/non-coding features.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, which is crucial for assessing the functional impact of coding mutations on driver proteins.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most biologically relevant transcript for each gene.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers, useful for linking variants to protein-level functional changes.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful for checking if the identified somatic variants overlap with known mouse variation data.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Provides sequence-based prediction of whether missense changes affect protein function (available for mouse).

  Reason: Necessary for assessing the impact of variants on splice sites, which is relevant for both coding and regulatory/intronic regions.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --symbol --hgvs --regulatory --biotype --domains --canonical --protein --check_existing --sift --maxentscan --phenotypes --plugin MaxEntScan --plugin Phenotypes
```
*Note: Web interface users should select "Symbol", "HGVS", "Regulatory", "Biotype", "Domains", "Canonical", "Protein", and the "MaxEntScan" and "Phenotypes" plugins. Ensure the species is set to Mus musculus.*
