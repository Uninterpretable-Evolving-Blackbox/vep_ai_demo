### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the Ensembl/GENCODE core annotation set to drive consequence calculation, which is the standard requirement for all species.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for the user's goal of identifying impacts on regulatory regions (promoters, enhancers, etc.) in the non-coding genome.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize consequences by flagging the canonical transcript for each gene.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides the transcript or regulatory feature type (e.g., lincRNA, enhancer), which is critical for characterizing non-coding impacts.

✗ hgvs [source: hgvs, priority=optional] confidence: medium
  Reason: While useful, it is marked as optional and can conflict with other summary/severity flags if the user decides to restrict results later.

✗ most_severe [source: most_severe, priority=optional] confidence: medium
  Reason: Disabled to avoid conflicts with other potential annotation outputs; allows the user to see all potential consequences in the non-coding space.

✗ af_gnomade [source: af_gnomade, priority=NOT APPLICABLE] confidence: high
  Reason: gnomAD is human-only; zebrafish data is not supported by this option.

✗ dbnsfp [source: dbnsfp, priority=NOT APPLICABLE] confidence: high
  Reason: dbNSFP is a human-specific meta-resource.

✗ clinvar [source: clinvar, priority=NOT APPLICABLE] confidence: high
  Reason: ClinVar is a human-specific clinical database.

✗ cadd [source: cadd, priority=NOT APPLICABLE] confidence: high
  Reason: CADD is a human-only prediction tool.

✗ uniprot [source: uniprot, priority=no priority] confidence: medium
  Reason: Since the focus is regulatory/non-coding, protein-level identifiers like UniProt are less relevant for the primary analysis goal.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --regulatory --canonical --biotype
```
*Note: On the Ensembl Web Interface, ensure "Regulatory" and "Biotype" are checked in the optional settings. The `--cache` flag is required for local command-line execution.*
