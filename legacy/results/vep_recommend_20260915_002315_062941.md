## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

### 2. Recommended Options
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Helps identify the most functionally significant isoforms, which aligns with the goal of identifying impacts on reliable transcripts.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for distinguishing between protein-coding, regulatory, and other non-coding features in a top-line summary.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Provides a quick way to identify the primary transcript for a gene, aiding in the "top-line" summary requirement.
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Standard practice to use the Ensembl/GENCODE core annotations for consequence calculation.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs/structural variants to assess if a gene is sensitive to changes in copy number.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically provides population frequency context for structural variants/CNVs, which is a primary goal.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Adds exon/intron numbering, providing necessary detail for the functional consequences of the variants.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Required to capture disruptions to regulatory or non-coding elements as requested.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds HGNC gene symbols to make the top-line summary human-readable and useful.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Provides Transcript Support Level, which aids in identifying the reliability of the transcripts being annotated.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: This is for exome-only frequencies; gnomad_sv is the more appropriate choice for structural variants.
✗ check_existing [source: check_existing] confidence: medium
  Reason: While useful for finding rsIDs, the user's primary focus is on the impact of the SVs themselves rather than matching existing short variants.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily for small variants and is often not applicable/useful for large-scale CNVs in a "top-line" summary.
✗ most_severe [source: most_severe] confidence: high
  Reason: This flag conflicts with several other recommended tools like 'symbol' and 'tsl' that are needed for a comprehensive summary.
✗ pick [source: pick] confidence: high
  Reason: Restricts output to one line; the user wants to see impacts on both coding and regulatory elements, so we should not restrict the results.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --plugin DosageSensitivity --plugin gnomad_sv --appris --biotype --canonical --regulatory --symbol --tsl --numbers
```
