  Reason: Using the default or standard Ensembl/GENCODE core annotation set is appropriate for general consequence calculation across various transcript structures, as suggested by the scenario's focus on gene disruption.

  Reason: Providing the gene symbol (e.g., TP53) is crucial for top-line interpretation and is generally needed for clinical/research reporting, as noted in the knowledge base.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: For structural variants, providing exon/intron numbering gives necessary positional context (Exon/Intron format), which is more useful than detailed sequence consequence types when looking at large alterations.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Identifying the transcript type (e.g., protein\_coding, lincRNA) helps filter the results and understand the functional consequence of the structural change, as recommended.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Since the input contains structural variants, using the specialized gnomAD_SV annotation is highly recommended to filter out common, benign structural changes and improve interpretability, as noted in the knowledge base.
✗ hgvs [source: hgvs] confidence: medium
  Reason: While often useful, HGVS nomenclature is complex to generate accurately for large structural variants and might be overkill for a "quick top-line call." It can be added later if required.
✗ af_gnomade [source: af_gnomade] confidence: medium
  Reason: This measures allelic frequencies, which are more critical for point mutations. While gnomAD_SV covers structural frequencies, general population frequency checks might be redundant or confusing for large CNVs at this stage.
✗ af_gnomadg [source: af_gnomadg] confidence: medium
  Reason: Similar to af_gnomade, this is less critical for structural CNV interpretation compared to the dedicated gnomAD_SV plugin.
✗ tsl [source: tsl] confidence: low
  Reason: TSL is useful for transcript assessment but is not mandatory for the top-line assessment of large structural disruption.
✗ most_severe [source: most_severe] confidence: high
  Reason: Since you want to assess *which* genes are disrupted, you need to see the full consequence information across all overlapping transcripts, making the summary collapse of `--most_severe` undesirable.
✗ summary [source: summary] confidence: high
  Reason: Similar to `--most_severe`, using `--summary` would collapse potentially multiple, distinct disruption signals across different transcripts into a single field, reducing the information needed for a thorough, top-line assessment.
✗ codons [source: codons] confidence: high
  Reason: Not applicable or recommended. This option is not available in the provided list.
✗ domains [source: domains] confidence: low
  Reason: Domain annotation is most useful for point mutations affecting protein structure. For large SVs, gene/transcript boundaries are a better metric for primary impact assessment.
✗ loeuf [source: loeuf] confidence: low
  Reason: LOEUF is designed for quantifying loss-of-function from point mutations, not the gross disruption caused by large CNVs/SV.
✗ appris [source: appris] confidence: low
  Reason: This annotation is highly specific to isoform selection, which is generally less critical for the broad assessment of structural disruption.
✗ biotype [source: biotype] confidence: high
  Reason: This was already selected above but reiterating its importance: it helps characterize the functional element being disrupted (coding vs. regulatory).
✓ lineage_info [source: lineage_info] confidence: low
  Reason: Not provided in the list. If this were available, it would be optional, but based on the provided list, we stick to the core recommendations.
✗ all other plugins/options (e.g., clinvar, cadd, sift, etc.) [source: various] confidence: high
  Reason: Most other plugins (CADD, SIFT, ClinVar, etc.) are optimized for point mutations (single nucleotide changes). They provide little actionable information for interpreting the *scale* of disruption caused by large SVs/CNVs, leading to noisy or irrelevant output for this initial screen.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --offline --alt-allele=N --allele_number=1 --transcript_sequence_version=YYYYMMDD --snp --somatic --structural --plugin gnomAD_SV
```
*(Note: The --cache flags would require local plugin data files for gnomAD_SV, which must be pre-downloaded for this plugin.)*
