**Date:** 2026-09-09T22:43:46.489622

## User Query
I am currently reviewing exome sequencing results from a cohort of mice used in our recent developmental study. We have identified several single-letter changes and small additions or deletions throughout the genome. For my preliminary report, I just need to quickly identify which of these variations actually alter the protein sequence or create an early stop signal within the coding regions.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (mouse cohort)
- **origin**: germline (implied by "cohort of mice used in our recent developmental study," typically representing the baseline genetic makeup of the experimental group)
- **variant_size_class**: small (single-letter changes and small additions/deletions)
- **region_focus**: coding (explicitly requested: "within the coding regions")
- **analysis_goal**: basic-consequence (goal is to "quickly identify" functional impact like protein alterations or stop signals)

### 2. Recommended Options
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between protein-coding and other transcript types, which is essential for a coding-focused study.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize the most functionally relevant transcript for each gene to simplify the "quick" identification process.
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Necessary to define the primary annotation set driving the consequence calculations.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, which is highly relevant for understanding if a protein-altering change hits a functional site.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standardized nomenclature for the identified protein-altering changes.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon and intron numbering, making it easier to report exactly where the stop signals or changes occur.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), which is crucial for linking the variants to protein-level changes.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to make the preliminary report readable and easy to interpret.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to see if these mouse variants have been previously catalogued in other databases.
✓ coding_only [source: coding_only, priority=optional] confidence: high
  Reason: Since the user specifically wants to focus on coding regions and stop signals, this restricts the output to increase speed and reduce noise.
✗ most_severe [source: most_severe] confidence: high
  Reason: Enabling this would conflict with the recommended `--hgvs`, `--symbol`, and `--protein` options.
✗ af_gnomad [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only database.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is a human-only resource.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only database.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --biotype --canonical --core_type --domains --hgvs --numbers --protein --symbol --check_existing --coding_only
```
*(Note: On the Ensembl VEP Web Interface, ensure "Coding only" is selected in the 'Restrict results' or filtering section to mimic the `--coding_only` flag.)*
