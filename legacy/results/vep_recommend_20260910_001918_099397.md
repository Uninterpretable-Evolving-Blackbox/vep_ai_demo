## User Query
I’m working through some human tumour sequencing data where we're specifically looking for large-scale changes in the DNA structure, like deletions or duplications. A lot of these structural changes are landing in the regions outside of the actual genes, so I need a way to quickly figure out if these stretches of missing or extra DNA might be affecting how genes are turned on or off. It would also be really helpful to see how common these types of variations are in the general healthy population so I can better judge whether a finding looks like a potential driver for the cancer or just a common variation.

- **region_focus**: regulatory-noncoding (indicated by "outside of the actual genes... affecting how genes are turned on or off")
- **analysis_goal**: clinical-interpretation, population-frequency (indicated by "judge whether a finding looks like a potential driver... or just a common variation")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is recommended for high-quality transcript/gene consequence calculation in human studies.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for the user's goal to identify if structural changes affect promoters, enhancers, or CTCF binding sites.

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs (deletions/duplications) to determine if the affected gene is sensitive to changes in copy number (e.g., pHaplo scores).

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically enables the annotation of structural variants using gnomAD SV allele frequencies to distinguish drivers from common population variants.

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores to help assess the functional constraint of the genes being affected by the CNVs.

✓ mastermind [source: mastermind, priority=recommended] confidence: high
  Reason: Useful for clinical interpretation by linking variants to existing clinical evidence in medical literature.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps identify the nature of the affected feature (e.g., lincRNA, protein_coding) in non-coding regions.

✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Assists in clinical interpretation by retrieving phenotype associations for the affected genes.

✓ cadd [source: cadd, priority=recommended] confidence: high
  Reason: Provides a combined deleteriousness score which can help rank the potential impact of the variations.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Necessary to enable ClinVar and other co-located variant lookups.

✓ clinvar [source: clinvar, priority=recommended] confidence: high
  Reason: Provides clinical significance (pathogenic/benign) for co-located variants, critical for the user's goal of driver identification.

✓ pubmed [source: pubmed, priority=optional] confidence: medium
  Reason: Provides literature support for co-located variants, aiding clinical interpretation.

✗ hgvs [source: hgvs] confidence: high
  Reason: Not applicable; HGVS nomenclature is typically used for small variants (SNVs/Indels) and is often incompatible with the summary/pick logic used in complex workflows.

✗ coding_only [source: coding_only] confidence: high
  Reason: The user specifically wants to look at regions "outside of the actual genes" (non-coding/regulatory).

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is optimized for missense variants; the user is focused on structural CNVs.

✗ spliceai [source: spliceai] confidence: high
  Reason: SpliceAI is designed for small variants affecting splicing; not the primary tool for large-scale CNVs.

✗ most_severe [source: most_severe] confidence: high
  Reason: Using `most_severe` would conflict with many of the specialized plugins and regulatory outputs needed for a comprehensive non-coding analysis.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --plugin DosageSensitivity --plugin Mastermind --plugin Phenotypes --plugin CADD --plugin LOEUF --custom gnomad_sv,gnomAD_SV_VCF_PATH,type=exact,overlap_cutoff=exact --check_existing --plugin ClinVar --plugin PubMed --regulatory --biotype
```
*(Note: Replace `gnomAD_SV_VCF_PATH` with the actual path to your local gnomAD SV file. In the Ensembl Web Interface, these correspond to the "Regulatory Build", "Dosage Sensitivity", and "gnomAD SV" checkboxes.)*
