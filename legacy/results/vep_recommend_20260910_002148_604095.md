## User Query
I am looking at some human tumor sequencing results and I have noticed several large sections of DNA that seem to be either extra or missing. I am especially interested in the areas that don't actually make proteins but instead act as control switches for genes, as I want to see if these big changes might be affecting how those genes work and contributing to the cancer. It is also really important for me to know how common these same types of variations are in healthy people so I can tell the difference between normal variation and something potentially dangerous. How should I configure my run to get all that info about the regulatory impact and the population background?

## Recommendation
### 1. Detected Scenario
- **species**: human (stated "human tumor sequencing")
- **origin**: somatic (stated "tumor sequencing")
- **variant_size_class**: structural-CNV (stated "large sections of DNA that seem to be either extra or missing")
- **region_focus**: regulatory-noncoding (stated "areas that don't actually make proteins but instead act as control switches")
- **analysis_goal**: clinical-interpretation, population-frequency (stated "tell the difference between normal variation and something potentially dangerous" and "how common these same types of variations are in healthy people")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard for clinical and population studies.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for the user's focus on "control switches" (promoters, enhancers, etc.) in non-coding regions.

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs (extra or missing DNA) to determine if the gene is sensitive to changes in copy number.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically required to assess the population frequency of structural variants (CNVs) in healthy populations.

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides context on the evolutionary constraint of genes, helping to prioritize potentially pathogenic CNVs.

✓ mastermind [source: mastermind, priority=recommended] confidence: high
  Reason: Helps with clinical interpretation by linking variants to existing medical literature.

✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Connects variants to known disease associations, aiding clinical interpretation.

✓ cadd [source: cadd, priority=recommended] confidence: high
  Reason: Provides a combined score for deleteriousness, useful for prioritizing non-coding impacts.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Necessary to distinguish between different types of non-coding elements (e.g., enhancers vs. lincRNA).

✓ clinvar [source: clinvar, priority=recommended] confidence: high
  Reason: Essential for clinical interpretation to see if the region/variant has been previously reported as pathogenic.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Enables the retrieval of ClinVar and other known variant data.

✓ pubmed [source: pubmed, priority=optional] confidence: medium
  Reason: Provides literature links to support clinical interpretation.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for coding variants; less applicable to large-scale structural CNVs in this context.

✗ coding_only [source: coding_only] confidence: high
  Reason: The user specifically wants to focus on regulatory-noncoding regions; this would hide their target data.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is designed for missense (coding) variants and is NOT APPLICABLE for structural/non-coding focus.

✗ sift [source: sift] confidence: high
  Reason: SIFT is a missense predictor and NOT APPLICABLE for structural CNVs.

✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen is a missense predictor and NOT APPLICABLE for structural CNVs.

### 3. Generated VEP Command
```
vep --input_file somatic_cnvs.vcf --output_file somatic_cnvs_annotated.txt --cache --plugin DosageSensitivity --plugin Mastermind --plugin Phenotypes --plugin CADD --plugin gnomad_sv --check_existing --clinvar --pubmed --regulatory --biotype --plugin LOEUF
```
*Note: For the `--plugin gnomad_sv` and `--plugin CADD`, you must provide the paths to the respective data files (e.g., `--dir_cache /path/to/cache`). On the Ensembl Web Interface, these correspond to checking the boxes for "Regulatory", "Dosage Sensitivity", "gnomAD SV", and "ClinVar".*
