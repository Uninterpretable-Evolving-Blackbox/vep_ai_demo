## User Query
I am currently processing a set of somatic mutations identified from mouse tumor sequencing to identify potential driver candidates in this model. We have a collection of SNVs and small indels derived from both WES and some supplemental WGS data, and I need to perform an initial, high-level annotation pass. The goal is to quickly categorize these variants based on their functional impact, specifically distinguishing between those falling within protein-coding sequences and those residing in regulatory or non-coding regions, so I can prioritize which mutations are worth more rigorous downstream analysis.

- **variant_size_class**: small (specified as "SNVs and small indels")
- **region_focus**: coding, regulatory-noncoding (specified as "distinguishing between those falling within protein-coding sequences and those residing in regulatory or non-coding regions")
- **analysis_goal**: basic-consequence (specified as an "initial, high-level annotation pass" to "quickly categorize these variants")

### 2. Recommended Options
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for categorizing variants by the type of feature they hit (e.g., protein_coding, miRNA, lincRNA), which aligns with the goal of distinguishing between coding and non-coding regions.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize variants by identifying the most reliable (canonical) transcripts for each gene, useful for high-level categorization.

✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Required to define the underlying annotation set driving the consequence calculation.

✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, helping to quickly categorize the functional impact of coding variants.

✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard nomenclature for the variants, which is a fundamental requirement for basic consequence reporting.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is necessary for a high-level understanding of where the variant falls within a gene structure.

✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), aiding in the categorization of coding-sequence impacts.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Enables the detection of overlaps with regulatory regions (promoters, enhancers, etc.), directly addressing the user's need to identify non-coding regulatory impacts.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, making the results human-readable and easier to categorize by gene name.

✗ most_severe [source: most_severe] confidence: high
  Reason: This option is a "Restrict results" setting that conflicts with many recommended descriptive fields like --hgvs, --symbol, and --domains.

✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: NOT APPLICABLE; this is a human-only frequency database.

✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-centric clinical database.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; this is a human-only meta-resource.
