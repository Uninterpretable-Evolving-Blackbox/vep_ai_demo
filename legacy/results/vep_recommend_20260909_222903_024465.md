## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential for providing the Ensembl/GENCODE base annotation required for all consequence calculations.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides HGNC gene symbols, making the results human-readable and useful for clinical/biological context.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Necessary to distinguish between protein-coding genes and regulatory elements (e.g., lincRNA, miRNA) hit by CNVs.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Required to capture disruptions to promoters, enhancers, and other regulatory regions as requested.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Provides Transcript Support Level to help identify the "most reliable transcripts" requested.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically annotates structural variants with gnomAD SV allele frequencies to help distinguish somatic hits from common germline SVs.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Crucial for CNVs/structural variants to understand the impact of gene dosage changes (e.g., pHaplo).
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to identify if the structural variant is already catalogued in databases like dbSNP.
✗ most_severe [source: most_severe] confidence: high
  Reason: The user requested a "top-line summary" but specifically wants to see effects on both coding and regulatory elements; `most_severe` would collapse these distinct consequences into one, losing the detail needed to see the regulatory disruption.
✗ summary [source: summary] confidence: high
  Reason: While the user asked for a "top-line summary," in VEP terms, the `--summary` flag collapses all transcript/consequence info into a single line, which would prevent seeing the specific "reliable transcript" or "regulatory element" details requested.
✗ sift [source: sift] confidence: high
  Reason: Missense predictors like SIFT are not applicable to structural variants/CNVs.
✗ polyphen [source: polyphen] confidence: high
  Reason: Missense predictors like PolyPhen are not applicable to structural variants/CNVs.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is designed for small variants (SNVs/indels) and is not applicable to structural variants.

### 3. Generated VEP Command
```bash
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --symbol --biotype --tsl --regulatory --gnomad_sv <path_to_gnomad_sv.vcf.gz> --plugin DosageSensitivity --check_existing
```
*Note: The `--gnomad_sv` option requires a local path to a gnomAD SV VCF file. In the web interface, ensure "Regulatory Build" and "gnomAD SV" are selected.*
