### 2. Recommended Options
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Adds the biotype of the transcript or regulatory feature, which is essential for categorizing the functional impact of structural changes.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps identify if the structural variant affects the canonical transcript, simplifying the assessment of primary consequences.
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the Ensembl/GENCODE core annotation to drive consequence calculations, which is the standard approach for this scenario.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs as it provides gene dosage sensitivity scores (e.g., pHaplo) to assess the impact of deletions/duplications.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically designed to annotate structural variants with gnomAD structural-variant allele frequencies.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which helps in quickly understanding the genomic context of the consequence.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Enables overlap detection with regulatory regions (promoters, enhancers), meeting the user's requirement for non-coding analysis.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds HGNC gene symbols, making the output human-readable and easier to interpret quickly.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Adds Transcript Support Level to help prioritize high-confidence transcript annotations.
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Adds APPRIS isoform annotation to help identify functionally important transcripts.

  Reason: Disabled because it conflicts with several useful annotation flags like symbol and tsl which are needed for a comprehensive (even if "quick") view.

  Reason: The user explicitly requested analysis of regulatory and non-coding regions.

  Reason: The user wants to identify consequences across both regions; restricting to a single line per variant might hide regulatory impacts if a coding impact is also present.
