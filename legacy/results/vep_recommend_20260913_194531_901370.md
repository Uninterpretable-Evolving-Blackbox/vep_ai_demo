## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation

- **region_focus**: coding, regulatory-noncoding (stated "protein-coding regions... disruptions to regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency (stated "top-line summary of their functional consequences" and "context regarding population allele frequencies")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential for driving consequence calculation using Ensembl/GENCODE core annotations.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides gene symbols (e.g., TP53) to make the functional consequences human-readable.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Necessary to distinguish if an SV hits a protein-coding gene, lincRNA, or other regulatory feature.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Required to identify overlaps with promoters, enhancers, and other regulatory regions as requested.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically targets the user's SV/CNV class to provide population frequencies for structural variants.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps identify "most reliable transcripts" by providing Transcript Support Level rankings.
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Adds APPRIS isoform annotation to help prioritize functionally important transcripts.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs to identify if the affected gene is sensitive to dosage changes (e.g., pHaplo).
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful for identifying known variants co-located with the SVs.
✓ clinvar [source: clinvar, priority=optional] confidence: medium
  Reason: Helps identify if the structural change overlaps with known clinical significance.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is typically used for small variants (SNVs/Indels) and is less applicable for structural/CNV summary.
✗ sift [source: sift] confidence: high
  Reason: SIFT is a missense predictor for small variants and is not applicable to structural/CNV variants.
✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen is a missense predictor for small variants and is not applicable to structural/CNV variants.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is designed for small variants and is not applicable to structural/CNV variants.
✗ most_severe [source: most_severe] confidence: high
  Reason: User wants a "summary" but also wants to see impacts on "most reliable transcripts" and "regulatory elements"; --most_severe would collapse this detail.
✗ summary [source: summary] confidence: high
  Reason: Collapsing results into a single line would prevent the user from seeing the distinction between coding and regulatory impacts.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --format vcf --vcf --symbol --biotype --regulatory --gnomad_sv --tsl --appris --plugin DosageSensitivity --check_existing --plugin ClinVar
```
*Note: The `--plugin ClinVar` and `--plugin DosageSensitivity` require the respective plugin data files to be present in your cache directory. Web interface users should select these via the "Plugins" and "Regulatory" dropdowns.*
