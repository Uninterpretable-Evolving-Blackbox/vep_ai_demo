## User Query
I have germline Mus musculus WES data; I need to identify protein-altering SNVs and indels in coding regions and assess their predicted functional pathogenicity.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (*Mus musculus* specified)
- **origin**: germline (specified)
- **variant_size_class**: small (SNVs and indels)
- **region_focus**: coding (specified "protein-altering" and "coding regions")
- **analysis_goal**: clinical-interpretation (assessing "predicted functional pathogenicity")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is recommended for non-human species to drive consequence calculation.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard HGVS nomenclature for coding variants, which is essential for reporting protein-altering changes.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information (Pfam, etc.), which helps interpret the functional impact of a mutation within a specific protein region.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, facilitating easier interpretation of the biological context.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Identifies the canonical transcript, which is a standard practice to prioritize the most representative protein-coding isoform.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), which is crucial for linking SNVs/indels to protein-level changes.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides transcript biotypes to confirm that the consequences are occurring in protein-coding transcripts.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Provides sequence-based scoring for splice site impacts, which is important for assessing the pathogenicity of indels/SNVs near exon boundaries.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Adds exon/intron numbering (e.g., 7/27), helping to localize the variant within the gene structure.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Since the species is non-human (mouse), SIFT can provide species-specific predictions of whether an amino acid substitution affects protein function.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Retrieves phenotype associations to assist in the clinical interpretation of the functional impact.
✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Helps assess if a premature stop codon might escape nonsense-mediated decay, which is relevant for pathogenicity assessment.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Restricts output to coding consequences, which aligns with the user's focus on protein-altering variants.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful for seeing if these germline variants have been previously cataloged in other databases.
✓ uniprot [source: uniprot, priority=optional] confidence: medium
  Reason: Adds UniProt accessions for better integration with protein-level functional databases.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because it conflicts with recommended functional prediction flags like `--sift`, `--hgvs`, and `--symbol`.
✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only database.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only database.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is a human-only meta-resource.
✗ polyphen [source: polyphen] confidence: high
  Reason: NOT APPLICABLE; PolyPhen is a human-only prediction tool.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --species mus_musculus --hgvs --domains --symbol --canonical --protein --biotype --sift --maxentscan --numbers --phenotypes --nmd --coding_only --check_existing --uniprot
```
