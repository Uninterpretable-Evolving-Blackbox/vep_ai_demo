**Date:** 2026-09-10T00:36:41.106320

## User Query
I have somatic SNVs and indels from a mouse tumor. I need to identify the functional impact of both coding and regulatory variants for a preliminary pathogenicity assessment.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (mouse)
- **origin**: somatic (tumor)
- **variant_size_class**: small (SNVs and indels)
- **region_focus**: coding, regulatory-noncoding (specified in request)
- **analysis_goal**: clinical-interpretation (pathogenicity assessment)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the Ensembl/GENCODE core annotation is the standard for driving consequence calculation in non-human species.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Essential for clinical-grade reporting to provide standardized HGVS nomenclature for both coding and non-coding variants.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Helps assess pathogenicity by identifying if a variant disrupts known protein domains.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides gene symbols to make the somatic mutation list interpretable for biological context.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Required to fulfill the user's goal of assessing impact on regulatory regions.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize variants hitting the most representative transcript of a gene.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Provides Ensembl protein IDs (ENSP), crucial for linking somatic mutations to protein-level changes.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for distinguishing between coding genes and the regulatory non-coding elements requested.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Provides sequence-based splice site scoring, which is critical for assessing indel/SNV impact on splicing in coding regions.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is necessary for accurate reporting of variant positions.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: medium
  Reason: Useful for preliminary pathogenicity assessment by linking genes to known biological phenotypes.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Provides a prediction of whether a missense substitution affects protein function, supported for species with SIFT data.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Can identify if the somatic variant has been previously recorded in existing mouse variation databases.
✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Helps assess if a coding variant might trigger nonsense-mediated decay, a key mechanism in somatic driver identification.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because it conflicts with several recommended options like --hgvs, --symbol, and --sift, which are needed for detailed clinical interpretation.
✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only resource.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only database.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is a human-only resource.

### 3. Generated VEP Command
```
vep --input_file somatic_variants.vcf --output_file output.txt --cache --hgvs --domains --symbol --regulatory --canonical --protein --biotype --sift --maxentscan --numbers --phenotypes --check_existing --plugin NMD
```
*Note: On the Ensembl VEP Web Interface, ensure "Regulatory" is checked under the 'Additional Annotation' section and "Sift" is selected under 'Plugin/Score' options.*
