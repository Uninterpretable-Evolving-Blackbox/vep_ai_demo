## User Query
I am working with human somatic whole exome sequencing data from a series of tumor biopsies and have identified several structural variants and copy number alterations that I need to interpret. Since I am still learning the ropes of setting up my annotation pipeline, I was wondering how I should approach this if my primary goal is just to get a quick top-line call on which protein-coding genes are being disrupted or lost by these large genomic changes, without necessarily needing an exhaustive breakdown of every small-scale nucleotide change at this stage.

## Recommendation
### 1. Detected Scenario
- **species**: human (User mentioned "human somatic whole exome sequencing")
- **origin**: somatic (User mentioned "tumor biopsies")
- **variant_size_class**: structural-CNV (User mentioned "structural variants and copy number alterations")
- **region_focus**: coding (User mentioned "which protein-coding genes are being disrupted")
- **analysis_goal**: basic-consequence (User requested a "quick top-line call" rather than an exhaustive breakdown)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard starting point for consequence calculation in human studies.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Essential for a "top-line call" as it provides the HGNC gene symbols (e.g., TP53) to identify disrupted genes easily.

✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps prioritize the reliability of the transcript annotations used for the consequence calculation.

✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Helps identify the most functionally important isoforms, which is critical when interpreting gene disruption.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Allows the user to quickly confirm if the disrupted region is indeed protein_coding or another type.

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNV/structural variant analysis to identify if the loss or gain of a gene copy is likely to be pathogenic based on the Collins rCNV catalogue.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which helps in understanding the scale of the disruption within the gene.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Crucial for structural variants to determine if the observed CNV is a known common variation in the population.

✓ loeuf [source: loeuF, priority=recommended] confidence: high
  Reason: Provides context on the gene's tolerance to loss-of-function, helping to interpret the impact of a CNV-driven loss.

✗ hgvs [source: hgvs] confidence: high
  Reason: The user specifically requested to avoid an "exhaustive breakdown of every small-scale nucleotide change."

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: This plugin is optimized for missense single nucleotide variants, which are not the focus of this structural/CNV analysis.

✗ most_severe [source: most_severe] confidence: medium
  Reason: While useful for simplification, it conflicts with several recommended annotation flags (like symbol and tsl) which are needed for a meaningful "top-line" summary.

✗ regulatory [source: regulatory] confidence: high
  Reason: The user is focused on coding region disruption and gene loss, making regulatory region overlap a lower priority for this specific goal.

### 3. Generated VEP Command
```bash
vep --input_file <input.vcf> --output_file <output.txt> --cache --symbol --tsl --appris --biotype --dosage_sensitivity --numbers --custom <gnomAD_SV_VCF>,type=exact,overlap_cutoff=90 --plugin LOEUF --format vcf
```
*Note: On the Ensembl Web Interface, ensure you select "Human" as the species and check the boxes for Gene Symbol, Transcript Support Level, Biotype, and use the Custom/Plugin sections for Dosage Sensitivity and gnomAD SV.*
