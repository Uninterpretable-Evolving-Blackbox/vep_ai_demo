## User Query
I am currently reviewing exome sequencing results from a cohort of mice used in our recent developmental study. We have identified several single-letter changes and small additions or deletions throughout the genome. For my preliminary report, I just need to quickly identify which of these variations actually alter the protein sequence or create an early stop signal within the coding regions.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard for driving consequence calculations.

✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard nomenclature for the coding changes identified, which is essential for reporting protein-altering variants.

✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Helps identify if the protein-altering changes fall within known functional domains (Pfam, etc.), which is useful for developmental studies.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to make the results interpretable for a preliminary report.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps focus on the most biologically relevant transcript for each gene.

✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), allowing for direct linking to protein-level changes.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Confirms the transcript type (e.g., protein_coding) to ensure the focus remains on coding regions.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon and intron numbering (e.g., 7/27) which is standard for describing variant locations in reports.

✗ coding_only [source: coding_only] confidence: medium
  Reason: While the user is interested in coding regions, the goal is "basic-consequence." Standard VEP output includes the consequence type (e.g., missense, stop_gained) which allows the user to filter for coding effects without strictly restricting the transcript selection.

✗ most_severe [source: most_severe] confidence: medium
  Reason: This option conflicts with several recommended reporting options like `--hgvs`, `--symbol`, and `--protein`. It is better to see the full consequence data for a preliminary report.

✗ af_gnomad [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE. This is a human-only database.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE. This is a human-only resource.

✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE. ClinVar data is human-centric.
