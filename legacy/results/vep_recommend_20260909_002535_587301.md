**Date:** 2026-09-09T00:25:35.587732

## User Query
I am currently reviewing exome sequencing results from a cohort of mice used in our recent developmental study. We have identified several single-letter changes and small additions or deletions throughout the genome. For my preliminary report, I just need to quickly identify which of these variations actually alter the protein sequence or create an early stop signal within the coding regions.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (User specifies "mice")
- **origin**: somatic (Implied by "developmental study" context, though typically exome is germline, the focus is on the impact of the variations found)
- **variant_size_class**: small (User specifies "single-letter changes and small additions or deletions")
- **region_focus**: coding (User specifies "within the coding regions")
- **analysis_goal**: basic-consequence (User specifies "identify which of these variations actually alter the protein sequence or create an early stop signal")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard starting point for consequence calculation in non-human species.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides HGVS nomenclature, which is essential for reporting protein-altering changes (e.g., p.Arg123Gly) in a standard format.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Since the goal is to see how variations alter protein sequence, knowing if they overlap functional protein domains is highly relevant.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to make the report readable and useful for biological interpretation.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize consequences by identifying if the variant hits the canonical transcript of the gene.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Provides the Ensembl protein identifier (ENSP) to link genomic changes to specific protein products.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Confirms the type of transcript (e.g., protein_coding) to ensure the focus remains on coding consequences.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering (e.g., 7/27), which is critical for describing the location of the variant within the gene.
✗ most_severe [source: most_severe] confidence: high
  Reason: This option is disabled because it conflicts with the recommended `--hgvs` and `--symbol` flags. It is better to see all consequences to understand the full impact.
✗ coding_only [source: coding_only] confidence: medium
  Reason: While the user is interested in coding regions, keeping this disabled allows for the context of flanking regions if needed, though it could be an optional add-on.
✗ af_gnomad [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE. The user is studying mice; gnomAD is a human-only database.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE. dbNSFP is a human-only resource.
✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE. ClinVar is a human-only clinical database.
✓ uniprot [source: uniprot, priority=optional] confidence: medium
  Reason: Optional add-on to link protein changes to UniProt accessions, aiding in the functional interpretation of the "protein sequence alterations" requested.

### 3. Generated VEP Command
```bash
vep --input_file input.vcf --output_file output.txt --cache --format vcf --vcf --symbol --hgvs --canonical --protein --biotype --domains --numbers --plugin UniProt --dir_cache /path/to/vep_cache
```
*Note: On the Ensembl VEP Web Interface, ensure you select the correct Mouse genome assembly and check the boxes for Gene Symbol, HGVS, Canonical, Protein ID, Biotype, Domains, and Numbers.*
