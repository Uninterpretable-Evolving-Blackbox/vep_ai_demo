**Date:** 2026-09-09T22:28:49.056440

## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation
### 1. Detected Scenario
- **species**: human (specified as "human tumor-only")
- **origin**: somatic (specified as "tumor-only... somatic hits")
- **variant_size_class**: structural-CNV (specified as "structural variants and copy number alterations")
- **region_focus**: coding, regulatory-noncoding (specified as "protein-coding regions... disruptions to regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency (specified as "top-line summary of functional consequences" and "context regarding population allele frequencies")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is standard for providing the primary consequence backbone.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds HGNC gene symbols to make results human-readable, which is essential for a "top-line summary."
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Adds Transcript Support Level to help identify the most reliable/well-supported transcripts as requested.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Essential for distinguishing between protein-coding and non-coding (regulatory) features.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Specifically requested to capture disruptions to regulatory or non-coding elements.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs/structural variants to identify if the affected gene is sensitive to dosage changes (e.g., haploinsufficiency).
✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores to help assess the functional constraint of the genes being hit.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to help quickly summarize the location of the consequence.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Essential for CNV analysis; provides allele frequencies for structural variants from gnomAD SV to distinguish somatic from germline.
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Helps identify the most functionally important isoforms (principal transcripts) as requested.
✗ hgvs [source: hgvs] confidence: high
  Reason: Disabled to avoid conflicts with the summary/symbol/most_severe workflow and because HGVS is often less useful for large structural variants than gene-level impact.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because the user wants to "capture all relevant information" including regulatory impacts; `--most_severe` would collapse these into a single term, potentially hiding non-coding consequences.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: Not applicable as the primary focus is structural/CNV rather than missense point mutations.
✗ spliceai [source: spliceai] confidence: high
  Reason: Not applicable as the focus is on structural/CNV rather than single nucleotide splice-site predictions.
✗ coding_only [source: coding_only] confidence: high
  Reason: Explicitly requested to include regulatory/non-coding elements; `--coding_only` would filter those out.

### 3. Generated VEP Command
```
vep --input_file input.vcf --output_file output.txt --cache --symbol --tsl --biotype --regulatory --dosage_sensitivity --loeuf --numbers --appris --plugin gnomad_sv,/path/to/gnomad_sv.vcf.gz --check_existing
```
*Note: The `--check_existing` flag is included to allow for the retrieval of population frequencies and ClinVar data if co-located with known variants. The `--plugin gnomad_sv` requires a local path to the gnomAD SV VCF file. For web interface users, ensure the 'Regulatory Build' and 'gnomAD' checkboxes are selected.*
