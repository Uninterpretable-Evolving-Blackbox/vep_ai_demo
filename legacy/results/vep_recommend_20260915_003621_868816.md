# VEP Recommendation

**Date:** 2026-09-15T00:36:21.868956

## User Query
I am currently working through some sequencing results from a mouse model of cancer and I need to figure out how to properly annotate the list of changes we've identified in the tumor tissue. We are looking at single letter changes as well as small additions or removals of DNA, and it is really important for my analysis that I can see both the impact on protein-coding sequences and any potential effects on the control regions surrounding the genes. Ultimately, I need to be able to tell which of these changes look like they might actually be driving the tumor progression.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (mouse model)
- **origin**: somatic (tumor tissue)
- **variant_size_class**: small (single letter changes and small additions/removals)
- **region_focus**: coding, regulatory-noncoding (impact on protein-coding and control regions)
- **analysis_goal**: clinical-interpretation (identifying potential drivers of tumor progression)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential for providing the base Ensembl/GENCODE annotation required for all consequence calculations.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides gene symbols to make the results more interpretable for biological/clinical context.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standardized nomenclature for the identified changes, which is critical for reporting and follow-up.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between protein-coding genes and other regulatory elements (e.g., lincRNA) in the control regions.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Specifically requested to look for effects on control regions (promoters, enhancers, etc.) via the Ensembl Regulatory Build.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Helps identify if somatic changes hit critical protein domains, aiding in driver identification.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps prioritize consequences on the most biologically relevant transcript.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers to link somatic changes to protein-level impacts.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Required for assessing the impact of variants on potential splice sites, which can be a driver mechanism.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: Provides species-specific (mouse) sequence-based prediction of whether missense changes affect protein function.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering to help localize the variant within the gene structure.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Helps link identified genes to known phenotypes, aiding the interpretation of driver candidates.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to see if the identified somatic changes overlap with known mouse variation databases.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Can be used as a post-processing filter to focus on coding impacts, but since regulatory focus is requested, I am not enabling it by default.
✗ most_severe [source: most_severe] confidence: high
  Reason: Conflicts with hgvs, symbol, and sift. For driver identification, you need full per-transcript detail rather than a single collapsed term.
✗ summary [source: summary] confidence: high
  Reason: Conflicts with the detailed annotation required for clinical-grade driver interpretation.
✗ clinvar [source: clinvar] confidence: high
  Reason: ClinVar is a human-only resource.
✗ af_gnomade [source: af_gnomade] confidence: high
  Reason: gnomAD is a human-only resource.
✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen is a human-only resource.
✗ cadd [source: cadd] confidence: high
  Reason: CADD is a human-only resource.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is a human-only resource.

### 3. Generated VEP Command
```
vep --input_file somatic_variants.vcf --output_file annotated_variants.txt --cache --symbol --hgvs --biotype --regulatory --domains --canonical --protein --maxentscan --sift --numbers --phenotypes --check_existing
```
*Note: On the Ensembl VEP Web Interface, ensure you select "Mouse" as the species and enable the "Regulatory" and "Plugin" checkboxes for MaxEntScan and Phenotypes.*
