### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential to use the Ensembl/GENCODE core annotation to drive consequence calculation.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, which is crucial for interpreting which genes are affected in a clinical/functional context.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides HGVS nomenclature, which is standard for reporting protein-altering variants.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP) to link variants to specific protein products.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps confirm the functional nature of the transcript (e.g., protein_coding) being annotated.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Flags the canonical transcript, helping to prioritize the most biologically relevant transcript for functional assessment.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information (Pfam, etc.), which is vital for assessing the functional impact of a protein-altering change.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: SIFT is available for species with variation data (like mouse) and provides a sequence-based prediction of amino acid substitution effects.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Provides sequence-based scoring for splice sites, which is important for assessing the impact of indels/SNVs near exon boundaries.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon and intron numbering (e.g., 7/27) to precisely localize the variant within the coding structure.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Retrieves phenotype associations for the genes, aiding in the functional interpretation of the findings.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Since the goal is to identify protein-altering variants in coding regions, this restricts the output to relevant consequences.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to see if the variant is already catalogued in Ensembl variation databases.
✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Predicts if a premature stop codon will escape nonsense-mediated decay, which is highly relevant for coding pathogenicity assessment.

### 3. Generated VEP Command
```
vep --input_file mouse_wes.vcf --output_file mouse_annotated.txt --cache --format vcf --everything --symbol --hgvs --protein --biotype --canonical --domains --sift --maxentscan --numbers --phenotypes --coding_only --check_existing --plugin NMD
```
*(Note: `--everything` is a shorthand, but for precise control in a script, use the individual flags listed above. On the Ensembl Web Interface, ensure "Non-human" settings are respected and human-specific plugins like ClinVar or gnomAD are unchecked.)*
