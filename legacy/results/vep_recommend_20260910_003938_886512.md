## User Query
I am working with human somatic whole exome sequencing data from a series of tumor biopsies and have identified several structural variants and copy number alterations that I need to interpret. Since I am still learning the ropes of setting up my annotation pipeline, I was wondering how I should approach this if my primary goal is just to get a quick top-line call on which protein-coding genes are being disrupted or lost by these large genomic changes, without necessarily needing an exhaustive breakdown of every small-scale nucleotide change at this stage.

## Recommendation
### 1. Detected Scenario
- **species**: human (stated: "human somatic")
- **origin**: somatic (stated: "tumor biopsies")
- **variant_size_class**: structural-CNV (stated: "structural variants and copy number alterations")
- **region_focus**: coding (stated: "protein-coding genes")
- **analysis_goal**: basic-consequence (stated: "quick top-line call... without necessarily needing an exhaustive breakdown")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Essential to drive the consequence calculation using the Ensembl/GENCODE annotation set.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides the HGNC gene symbols (e.g., TP53) required for a "top-line call" on disrupted genes.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps confirm if the disrupted regions are protein-coding or other types of features.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically identifies if these structural variants are common in the population using gnomAD-SV frequencies.
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs to identify if the gene is sensitive to changes in copy number (e.g., haploinsufficiency).
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering which is useful even for large-scale disruptions to see where the break occurs.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful to see if these SVs overlap with known variants in databases.
✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is intended for nucleotide/amino acid changes; not appropriate for large-scale CNVs/SVs.
✗ sift [source: sift] confidence: high
  Reason: SIFT predicts the effect of single nucleotide missense mutations; not applicable to structural variants.
✗ polyphen [source: polyphen] confidence: high
  Reason: PolyPhen predicts the impact of amino acid substitutions; not applicable to structural variants.
✗ cadd [source: cadd] confidence: high
  Reason: CADD scores are designed for small-scale variants (SNVs/indels); not applicable to large SVs.
✗ most_severe [source: most_severe] confidence: medium
  Reason: While the user wants a "top-line call," disabling this ensures we don't lose the context of which specific gene/biotype was hit in the summary.
✗ summary [source: summary] confidence: medium
  Reason: The user wants to know which genes are disrupted; a summary may collapse too much information.

### 3. Generated VEP Command
```bash
vep --input_file <input.vcf> --output_file <output.txt> --cache --symbol --biotype --gnomad_sv --dosage_sensitivity --numbers --check_existing --plugin DosageSensitivity,/path/to/plugin/DosageSensitivity.ini
```
*Note: On the Ensembl Web Interface, select "Human" as species, enable "Gene Symbol", "Transcript Biotype", "Exon/Intron numbering", and use the Custom/Plugin section to add gnomAD SV and Dosage Sensitivity.*
