## User Query
I am processing human germline sequencing data from a large-scale population cohort and have identified several large structural changes, such as deletions and duplications of DNA segments. I want to focus my analysis on these changes when they occur in regulatory regions that control gene activity, rather than just looking at the protein-coding parts of the genome. For these types of variations, I need to ensure my annotation process includes information on how common these changes are within the general population so I can identify which ones are truly rare.

## Recommendation
### 1. Detected Scenario
- **species**: human (explicitly mentioned "human germline")
- **origin**: germline (explicitly mentioned "germline sequencing data")
- **variant_size_class**: structural-CNV (identified "large structural changes, such as deletions and duplications")
- **region_focus**: regulatory-noncoding (explicitly mentioned "regulatory regions... rather than just looking at the protein-coding parts")
- **analysis_goal**: population-frequency (explicitly mentioned "how common these changes are... to identify which ones are truly rare")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is recommended for human species to ensure high-quality transcript mapping.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for this scenario as the user specifically wants to focus on regulatory regions (promoters, enhancers, etc.).

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs/structural variants to determine if the loss or gain of a genomic segment impacts gene dosage.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between different types of regulatory elements and non-coding transcripts in the non-coding focus area.

✓ frequency [source: frequency, priority=recommended] confidence: high
  Reason: Directly addresses the goal of determining how common these variants are in the population.

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides the gnomAD LOEUF score, which is a key metric for assessing the impact of loss-of-function/structural variation in the context of population constraints.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically provides allele frequencies for structural variants from gnomAD, which is critical for the user's CNV focus.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Recommended to cross-reference the input CNVs with known variants/rsIDs to aid in population comparison.

✓ clinvar [source: clinvar, priority=optional] confidence: medium
  Reason: Useful to see if identified structural changes have existing clinical significance documented.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for coding/short variants; not the priority for large-scale structural/CNV analysis in non-coding regions.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP is a meta-resource for missense/coding variants and is NOT APPLICABLE to non-coding/structural analysis.

✗ coding_only [source: coding_only] confidence: high
  Reason: The user explicitly wants to look at regulatory-noncoding regions, so restricting to coding regions would exclude the target data.

✗ dbscsnv [source: dbscsnv] confidence: high
  Reason: Primarily used for splice-site prediction in coding regions; not applicable to large structural CNVs in regulatory regions.

✗ sift [source: sift] confidence: high
  Reason: SIFT predicts the impact of amino acid substitutions; NOT APPLICABLE for non-coding/CNV analysis.

✗ polyphen [source: polyphen] confidence: high
  Reason: Polyphen predicts protein structure changes; NOT APPLICABLE for non-coding/CNV analysis.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --plugin gnomad_sv --plugin DosageSensitivity --plugin LOEUF --regulatory --frequency --biotype --check_existing --clinvar
```
*Note: On the Ensembl VEP Web Interface, ensure you select "Regulatory" in the regions and check the boxes for "Frequency", "Dosage Sensitivity", and "LOEUF". The gnomAD SV plugin may require a custom file path if running locally.*
