- **analysis_goal**: clinical-interpretation (*identify/assess functional pathogenicity* indicated)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Necessary to drive the consequence calculation using the Ensembl/GENCODE core annotation set.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, which is essential for biological and functional context.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Provides standard HGVS nomenclature for the variants, which is critical for reporting and downstream analysis.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Adds transcript biotype to help distinguish between protein-coding and non-coding transcripts.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP) to link variants to protein-level consequences.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Flags the canonical transcript, helping to prioritize the most biologically relevant transcript for each gene.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information (e.g., Pfam), which is vital for assessing if a variant hits a functional site.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is necessary for precise localization of the variant within the gene.
✓ sift [source: sift, priority=recommended] confidence: high
  Reason: SIFT is available for species with variation data (like mouse) and provides a sequence-based prediction of missense impact.
✓ maxentscan [source: maxentscan, priority=recommended] confidence: high
  Reason: Provides sequence-based scoring for splice sites, which is useful for indels potentially affecting splicing.
✓ phenotypes [source: phenotypes, priority=recommended] confidence: high
  Reason: Retrieves phenotype associations for the genes, aiding in the functional interpretation of the variant.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Checks for known short variants co-located with the input, which helps establish if the variant has been seen before.
✓ coding_only [source: coding_only, priority=optional] confidence: medium
  Reason: Restricts output to coding consequences, which aligns with the user's focus on WES data.

  Reason: gnomAD is a human-only resource and is NOT APPLICABLE for *Mus musculus*.

  Reason: PolyPhen is a human-only tool and is NOT APPLICABLE for *Mus musculus*.

  Reason: CADD is a human-only resource and is NOT APPLICABLE for *Mus musculus*.

  Reason: Disabled to allow for full per-transcript detail, which is preferred for thorough functional assessment.
✗ summary [source: summary] confidence: medium

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --species mus_musculus --symbol --hgvs --biotype --protein --canonical --domains --numbers --sift --maxentscan --phenotypes --check_existing --coding_only
```
*Note: The `--cache` flag requires the species-specific cache for Mus musculus to be installed locally. On the Ensembl Web Interface, these correspond to the checkboxes for Gene Symbol, HGVS, Transcript Biotype, Protein ID, Canonical, Domains, Exon/Intron Number, SIFT, MaxEntScan, Phenotypes, and Coding Only.*
