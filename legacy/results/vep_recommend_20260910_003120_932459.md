### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses Ensembl/GENCODE core annotations which are the standard for driving consequence calculations in this scenario.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds HGNC gene symbols to the output, making results more human-interpretable.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Helps distinguish between protein-coding genes and other features, supporting the coding region focus.

✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Adds Transcript Support Level to help evaluate the quality/evidence of the transcripts being annotated.

✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Provides APPRIS isoform annotation to identify functionally important transcripts.

✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Highly relevant for CNVs; provides pHaplo scores to indicate if a gene is sensitive to dosage changes (deletions/duplications).

✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores, which help assess the intolerance of a gene to loss-of-function variants.

✓ frequency [source: frequency, priority=recommended] confidence: high
  Reason: Enables frequency-based pre-filtering/reporting to address the population-frequency goal.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, which is useful for localizing the impact of the CNV within the gene structure.

✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Specifically provides allele frequencies for structural variants from gnomAD SV, directly addressing the analysis goal.

✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Enables checking for known variants (like rsIDs) co-located with the input, which helps cross-reference population data.

✓ clinvar [source: clinvar, priority=optional] confidence: medium
  Reason: Adds clinical significance from ClinVar, which is helpful when reviewing germline variants of interest.

✓ nmd [source: nmd, priority=optional] confidence: medium
  Reason: Predicts if a variant escapes nonsense-mediated decay, useful for assessing the impact of coding-region disruptions.

✗ hgvs [source: hgvs] confidence: high
  Reason: HGVS nomenclature is primarily used for small variants (SNVs/indels) and is not the priority for structural CNVs.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: dbNSFP aggregates scores for missense variants; it is not applicable for structural-CNV analysis.

✗ coding_only [source: coding_only] confidence: high
  Reason: While the user focuses on coding areas, disabling all non-coding reporting can sometimes hide important boundary information for CNVs; however, it is not explicitly "recommended" compared to simply using transcript-based consequence filtering.

✗ most_severe [source: most_severe] confidence: high
  Reason: Enabling this would conflict with several other recommended annotation options like `--symbol` and `--tsl`.

### 3. Generated VEP Command
```
vep --input_file input.vcf --output_file output.txt --cache --species human --symbol --biotype --tsl --appris --dosage_sensitivity --plugin LOEUF --frequency --numbers --custom gnomad_sv,gnomAD_SV_VCF_PATH,type=exact,overlap_cutoff=exact --check_existing --plugin ClinVar --plugin NMD
```
*Note: Replace `gnomAD_SV_VCF_PATH` with the actual path to your local gnomAD SV file. In the Ensembl Web Interface, these options correspond to the "Transcript" and "Population Frequency" settings and the "Plugins" section.*
