**Date:** 2026-09-15T00:22:40.006699

## User Query
I am starting to set up the pipeline for our human tumor-only whole genome sequencing data from a large cancer cohort, but I am still a bit unsure about how to best capture all the relevant information. We have identified several structural variants and copy number alterations, and my goal is to get a quick top-line summary of their functional consequences. Specifically, I need to see how these changes affect protein-coding regions—ideally identifying impacts on the most reliable transcripts—but I also want to capture any potential disruptions to regulatory or non-coding elements. Additionally, it would be really helpful if the results provided context regarding population allele frequencies so I can distinguish these somatic hits from common germline variation.

## Recommendation
### 1. Detected Scenario
- **species**: human (explicitly stated "human tumor-only")
- **origin**: somatic (indicated by "tumor-only whole genome sequencing" and "distinguish these somatic hits")
- **variant_size_class**: structural-CNV (stated "identified several structural variants and copy number alterations")
- **region_focus**: coding, regulatory-noncoding (stated "affect protein-coding regions... disruptions to regulatory or non-coding elements")
- **analysis_goal**: basic-consequence, population-frequency (stated "top-line summary of their functional consequences" and "context regarding population allele frequencies")

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard for determining transcript-level consequences.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Provides HGNC gene symbols, making the "top-line summary" human-readable and useful for clinical interpretation.
✓ tsl [source: tsl, priority=recommended] confidence: high
  Reason: Helps identify "the most reliable transcripts" by providing the Transcript Support Level (TSL) ranking.
✓ appris [source: appris, priority=recommended] confidence: high
  Reason: Identifies the most functionally important isoforms, supporting the goal of focusing on reliable transcripts.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Flags the canonical transcript for each gene, which is essential for a streamlined summary of functional impact.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Specifically requested to capture "disruptions to regulatory or non-coding elements."
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides the functional class of the feature (e.g., protein_coding, lincRNA), necessary for the "top-line summary."
✓ dosage_sensitivity [source: dosage_sensitivity, priority=recommended] confidence: high
  Reason: Critical for CNVs/structural variants to determine if a gene is sensitive to changes in copy number (dosage).
✓ loeuf [source: loeuf, priority=recommended] confidence: high
  Reason: Provides gnomAD LOEUF scores, which help assess the constraint of a gene to loss-of-function, useful for interpreting somatic hits.
✓ gnomad_sv [source: gnomad_sv, priority=recommended] confidence: high
  Reason: Essential for the "structural-CNV" class to provide population frequencies for structural variants.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Provides exon/intron numbering, contributing to the requested "basic consequence" summary.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled because it conflicts with several recommended information-rich flags like --symbol, --tsl, and --canonical.
✗ hgvs [source: hgvs] confidence: high
  Reason: Not applicable/priority for structural-CNV/somatic focus in this specific summary configuration.
✗ coding_only [source: coding_only] confidence: high
  Reason: User explicitly requested to capture "regulatory or non-coding elements."
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: Primarily for missense SNVs; not the priority for structural variants and CNVs.

### 3. Generated VEP Command
```
vep --input_file <input.vcf> --output_file <output.txt> --cache --symbol --tsl --appris --canonical --regulatory --biotype --dosage_sensitivity --plugin LOEUF --custom gnomad_sv,gnomAD_SV_VCF,type=exact,overlap_cutoff=exact --numbers
```
*Note: The `--custom` flag for `gnomad_sv` requires the local path to your gnomAD SV VCF file. In the Ensembl Web Interface, these are selected via the "Plugins" and "Custom Data" sections.*
