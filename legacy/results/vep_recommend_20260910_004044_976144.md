## User Query
I am working on a new project involving whole genome sequencing data from a large cohort of wild-type *Mus musculus* and I am trying to figure out how to properly set up my annotation pipeline. We have identified many germline SNVs and small indels, but since my research focuses specifically on the impact of variants in non-coding and regulatory regions like enhancers, I am struggling with the configuration. My goal is just to get a quick top-line assessment of whether these small variants fall within functional non-coding elements or have predicted effects in those areas.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (*Mus musculus* identified).
- **origin**: germline (user mentioned "germline SNVs and small indels").
- **variant_size_class**: small (user specified "SNVs and small indels").
- **region_focus**: regulatory-noncoding (user specified "impact of variants in non-coding and regulatory regions like enhancers").
- **analysis_goal**: basic-consequence (user wants a "quick top-line assessment").

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Using the default Ensembl/GENCODE core annotation is the standard and recommended approach for consequence calculation in non-human species.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Essential for this scenario as the user specifically wants to identify overlaps with regulatory regions like enhancers.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Helps identify the primary transcript for a gene, which is useful for context even in non-coding studies.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides the functional class of the feature (e.g., lincRNA, enhancer, promoter), which is critical for assessing non-coding impacts.

✗ hgvs [source: hgvs] confidence: high
  Reason: While useful, it is marked as optional and can conflict with other summary/severity flags; for a "quick top-line assessment," it is not strictly required.

✗ most_severe [source: most_severe] confidence: high
  Reason: This option restricts output to a single consequence, which may hide important regulatory overlaps in a non-coding study.

✗ af_gnomadg [source: af_gnomadg] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only database.

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is a human-only resource.

✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-specific clinical database.

✓ check_existing [source: check_existing] confidence: medium
  Reason: Recommended to see if the identified SNVs/indels have been previously cataloged in existing mouse variation databases.

### 3. Generated VEP Command
```
vep --input_file input.vcf --output_file output.txt --cache --regulatory --biotype --canonical --check_existing
```
*(Note: The `--regulatory` flag requires the Ensembl regulatory build to be present in your cache/data directory. On the Ensembl Web Interface, these correspond to the "Regulatory" and "Biotype" checkboxes.)*
