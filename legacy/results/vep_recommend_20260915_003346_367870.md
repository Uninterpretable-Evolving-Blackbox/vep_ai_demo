**Date:** 2026-09-15T00:33:46.368024

## User Query
I am currently processing a set of somatic mutations identified from mouse tumor sequencing to identify potential driver candidates in this model. We have a collection of SNVs and small indels derived from both WES and some supplemental WGS data, and I need to perform an initial, high-level annotation pass. The goal is to quickly categorize these variants based on their functional impact, specifically distinguishing between those falling within protein-coding sequences and those residing in regulatory or non-coding regions, so I can prioritize which mutations are worth more rigorous downstream analysis.

## Recommendation
### 1. Detected Scenario
- **species**: non-human (mouse)
- **origin**: somatic (mouse tumor sequencing)
- **variant_size_class**: small (SNVs and small indels)
- **region_focus**: coding, regulatory-noncoding (distinguish between protein-coding and regulatory/non-coding)
- **analysis_goal**: basic-consequence (initial, high-level annotation pass to categorize impact)

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the default Ensembl/GENCODE core annotation which is the standard for driving consequence calculation.
✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, essential for identifying which genes are being mutated in the tumor.
✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides transcript/feature biotype (e.g., protein_coding, lincRNA), which is necessary to fulfill the goal of distinguishing between coding and non-coding regions.
✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Adds HGVS nomenclature, which is standard for describing the functional impact of small variants.
✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, helping to characterize the functional impact of coding mutations.
✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Identifies canonical transcripts, which helps simplify the high-level categorization by focusing on the most representative transcript.
✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Enables overlap detection with regulatory regions (promoters, enhancers, etc.), directly addressing the requirement to identify regulatory-noncoding mutations.
✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), allowing for protein-level analysis of coding variants.
✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Adds exon/intron numbering, which is vital for the high-level categorization of variant location.
✓ check_existing [source: check_existing, priority=optional] confidence: medium
  Reason: Useful in somatic contexts to see if these variants are already documented in mouse variation databases.
✗ most_severe [source: most_severe] confidence: high
  Reason: Disabled to avoid conflicts with symbol, hgvs, and protein, and to allow for a full view of consequences during an initial assessment.
✗ summary [source: summary] confidence: high
  Reason: Disabled because a summary view hides the detailed consequence information needed to distinguish between coding and regulatory impacts.

✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only database.
✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; dbNSFP is a human-only resource.
✗ cadd [source: cadd] confidence: high
  Reason: NOT APPLICABLE; CADD is a human-only resource.

### 3. Generated VEP Command
```
vep --input_file mutations.vcf --output_file annotated_mutations.txt --cache --format vcf --vcf --symbol --hgvs --biotype --domains --canonical --regulatory --protein --numbers --check_existing
```
*Note: On the Ensembl Web Interface, ensure the species is set to Mouse (Mus musculus) and select the "Regulatory" and "Protein" checkboxes under the additional annotation sections.*
