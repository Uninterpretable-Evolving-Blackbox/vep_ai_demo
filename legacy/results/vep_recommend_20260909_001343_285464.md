## User Query
I am currently processing a set of somatic mutations identified from mouse tumor sequencing to identify potential driver candidates in this model. We have a collection of SNVs and small indels derived from both WES and some supplemental WGS data, and I need to perform an initial, high-level annotation pass. The goal is to quickly categorize these variants based on their functional impact, specifically distinguishing between those falling within protein-coding sequences and those residing in regulatory or non-coding regions, so I can prioritize which mutations are worth more rigorous downstream analysis.

### 2. Recommended Options
✓ core_type [source: core_type, priority=recommended] confidence: high
  Reason: Uses the standard Ensembl/GENCODE annotation driving consequence calculation, which is the default and recommended for this scenario.

✓ hgvs [source: hgvs, priority=recommended] confidence: high
  Reason: Adds HGVS nomenclature for coding variants, essential for standardizing the identification of driver candidates.

✓ domains [source: domains, priority=recommended] confidence: high
  Reason: Adds protein domain information, helping to assess if a somatic mutation hits a functional domain of a mouse protein.

✓ symbol [source: symbol, priority=recommended] confidence: high
  Reason: Adds gene symbols to the output, making it significantly easier to identify potential driver genes.

✓ regulatory [source: regulatory, priority=recommended] confidence: high
  Reason: Enables overlap detection with regulatory regions (promoters, enhancers) to satisfy the requirement of identifying non-coding regulatory mutations.

✓ canonical [source: canonical, priority=recommended] confidence: high
  Reason: Flags canonical transcripts, which is useful for prioritizing consequences in a high-level pass.

✓ protein [source: protein, priority=recommended] confidence: high
  Reason: Adds Ensembl protein identifiers (ENSP), which is crucial for linking somatic SNVs to protein-level changes.

✓ biotype [source: biotype, priority=recommended] confidence: high
  Reason: Provides the transcript/feature biotype (e.g., protein_coding, lincRNA), which helps distinguish between coding and non-coding regions.

✓ numbers [source: numbers, priority=recommended] confidence: high
  Reason: Adds exon/intron numbering, providing necessary context for the location of the mutation within a gene.

✗ most_severe [source: most_severe] confidence: medium
  Reason: While useful, it conflicts with several recommended reporting options like `--symbol` and `--hgvs`. For a high-level pass, seeing the full context is often preferred over a single restricted term.

✗ coding_only [source: coding_only] confidence: high
  Reason: Disabled because the user specifically requested to identify variants residing in "regulatory or non-coding regions."

✗ dbnsfp [source: dbnsfp] confidence: high
  Reason: NOT APPLICABLE; this is a human-only resource.

✗ af_gnomad [source: af_gnomade] confidence: high
  Reason: NOT APPLICABLE; gnomAD is a human-only database.

✗ clinvar [source: clinvar] confidence: high
  Reason: NOT APPLICABLE; ClinVar is a human-only database.
